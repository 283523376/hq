# 主数据同步配置与使用（仓库 / 物料分类 / 工单类型）

> 设计依据：`docs/superpowers/specs/2026-10-26-yx-wms-master-data-erp-sync-design.md`（已批准）
> 适用范围：永鑫WMS 主数据骨架。事务流程（采购/委外/盘点）不在本文范围。

## 1. 这一版做了什么

| 维度 | 本期落地 | 外部依赖就位后 |
|---|---|---|
| 仓库档案 | LB→「半成品仓」、MJ→「产成品仓」改名；新建 CJ 初级产成品仓、TC 涂层产成品仓；BD_STOCK 同步链路（白名单默认空） | 配 `stock-whitelist` + `stock-code-map` 即开始真实同步 |
| 物料分类 | 种子建 HALF/CJ/TC/CP 四个分类；BD_MATERIAL 分组映射链路（未配置时空转） | 配 `category-map` 即生效 |
| 工单类型 | `wms_work_order.order_type` 列 + 四枚举（客户/备库/委外/受托） | 配 `order-type-field` + `order-type-value-map` 即生效 |

## 2. 配置项

写在 `jeecg-boot/jeecg-module-system/jeecg-system-start/src/main/resources/application-dev.yml`，全部可缺省。
**不需要的项请整行删掉或注释掉，不要写成 `""`**——`Map` 类型字段写成空串会导致绑定失败、应用起不来。

```yaml
wms:
  sync:
    erp:
      kingdee:
        master-data:
          enabled: false                  # 主数据同步总开关；默认关
          org-id: "101"                   # BD_STOCK 组织过滤，留空=不同步（安全默认）
          stock-whitelist:                # 金蝶仓库编码白名单；不配置=不拉任何仓
            - "X.2.4"
          stock-code-map:                 # 金蝶编码 → WMS 仓库码；命中则只改名不改码
            "[X.2.4]": TC                 # 注意方括号：编码里的点会被 YAML/绑定当成嵌套层级
            "[02.001]": MJ
          category-map:                   # 金蝶物料分组前缀=分类编码；不配置=空转
            - "BC.1012=CP"
          order-type-field: ""            # 标量字段可以留空串：PRD_MO 上类型字段名
          order-type-value-map:           # 金蝶值 → WMS 工单类型；不配置=落 NULL
            "客户订单": "客户订单"
            "备库": "备库订单"
```

> 三条硬规则（有单测 `WmsKingdeePropertiesBindingTest` 兜底）：
> 1. `stock-code-map` / `order-type-value-map` 是 Map，**不能**写成 `""` 或逗号串；
> 2. `stock-code-map` 的键含点号时必须写成 `"[X.2.4]"`，否则会被解析成嵌套 map；
> 3. `stock-whitelist` / `category-map` 是 List，用 `- 项` 列表写；空列表等价于未配置。

配置变更后必须**重启后端**才生效（`@ConfigurationProperties` 不热更新）。

### 2.1 三个开关的关系

| 开关 | 作用 | 默认 |
|---|---|---|
| `wms.sync.erp.kingdee.enabled` | 金蝶集成**总闸**，关闭时任何同步都不打金蝶 | false |
| `wms.sync.erp.kingdee.master-data.enabled` | 只控制主数据维度 | false |
| `master-data.org-id` / `stock-whitelist` | 具体拉取范围 | 空=不同步 |

三者是 **AND** 关系：总闸关 ⇒ 主数据同步即使 enabled=true 也不执行（Job 与 Service 双层判断）。

## 3. 使用方式

### 3.1 前端入口

「基础管理 → 库区/库位」左侧库区树顶部：
- **同步金蝶** → `POST /wms/warehouse/sync-kingdee`
- **初始化档案** → `POST /wms/warehouse/init-master-data`

「基础管理 → 物料分类」：`POST /wms/materialCategory/sync-kingdee`

### 3.2 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/wms/warehouse/sync-kingdee` | 拉 BD_STOCK，返回 `{fetched, renamed, created, message}` |
| POST | `/wms/warehouse/init-master-data` | LB/MJ 改名 + CJ/TC 建档，幂等 |
| POST | `/wms/materialCategory/sync-kingdee` | 按 `category-map` 盖代表分组到分类行 |

### 3.3 定时任务

`WmsMasterDataSyncJob`（cron `0 0 3 * * ?`，每天 03:00）**默认不注册**。
只有 `master-data.enabled=true` 时启动期才注册；改成 false 重启会主动摘除（Quartz JDBC 存储下暂停不等于停止）。

## 4. 验证步骤（复制即用）

```bash
# ① 确认迁移已应用（重启后执行）
"/c/Program Files/MySQL/MySQL Server 8.0/bin/mysql.exe" -uroot -proot yongxin_wms -e \
"SELECT version,success FROM flyway_schema_history WHERE version='3.9.5.24';"

# ② 确认本地档案
"/c/Program Files/MySQL/MySQL Server 8.0/bin/mysql.exe" -uroot -proot yongxin_wms -e \
"SELECT warehouse_code,warehouse_name,warehouse_type,erp_stock_code FROM wms_warehouse ORDER BY warehouse_code;"

# ③ 确认四个分类
"/c/Program Files/MySQL/MySQL Server 8.0/bin/mysql.exe" -uroot -proot yongxin_wms -e \
"SELECT category_code,category_name,category_type,status FROM wms_material_category WHERE id LIKE 'CAT%' ORDER BY category_code;"
```

**白名单为空时触发同步**：返回 `fetched=0`、`wms_warehouse` 不新增任何行——这是**预期行为**，不是故障。

**临时验证一条白名单**：把 `stock-whitelist` 改成 `X.2.4` 并重启 → 触发同步 → 应新增/更新一行
`erp_stock_code='X.2.4'`、`erp_stock_name='涂层产成品仓'`、`warehouse_type='普通仓'`。
验证完**改回空并删掉这行测试数据**——否则日后配 `stock-code-map` 把 `X.2.4` 映射到 TC 时，
会因为该编码已被这个测试仓占用而报「已被 WMS 仓库占用」（系统会明确报错，不会静默覆盖）。

> 注意：`初始化档案` 是**覆盖式**操作——每次点击都会把 LB/MJ 的名称重置为「半成品仓/产成品仓」。
> 在界面上手工改过库区名后，不要再用它做「刷新」。

## 5. 外部依赖（客户/金蝶侧，不阻塞上线）

| 编号 | 待办 | 就位后动作 |
|---|---|---|
| E1 | PRD_MO 增加工单类型字段 | 配 `order-type-field` + `order-type-value-map` |
| E2 | 定义物料分类的金蝶来源（分组树或自定义字段） | 配 `category-map`（多对一，前缀匹配） |
| E3 | 金蝶建「初级产成品仓」并告知编码 | 回填 CJ 的 `erp_stock_code` 或加入白名单 |
| E4 | 客户拍板 101 组织下仓→金蝶映射 | 配 `stock-whitelist` + `stock-code-map` |

## 6. 已知限制

- **不改码**：`stock-code-map` 命中时只改仓库名称，`warehouse_code` 保持不变（被库位/库存/设备引用）。
- **工单类型兜底**：`order_type` 为空时前端展示「客户订单」（设计裁量点 D4）；如需改为显示 `—` 请提需求。
- **分类映射**：分类行上的 `erp_group_number/name` 只记**首个命中**的代表分组，多对一关系在配置里维护。
- **不灌全表**：白名单为空时一行都不拉——这是对「测试账套约 190 个仓」的保护，不要为了省事配成全量。
