## 1. 交付范围

| 流程 | 实现内容 |
| --- | --- |
| CK-001 半成品领料 | 扫码工单 → 金蝶 `PRD_PPBOM` 取需求（取不到可手工录入，`requirement_source=手工`）→ 立库 FIFO 分配并锁定 → 下发 WCS 堆垛机任务 → 设备回执 → 取料确认（扣库存、释放锁定）→ 同步金蝶 `PRD_PickMtrl` |
| CK-002 成品销售 | 录入销售订单（同步金蝶 `SAL_SaleOrder`）→ 敏捷仓按料箱 FIFO 分配 → 下发 RMS SCR 出库任务 → 接驳分拣至出货口 → 复核（扫描码/数量）→ 确认出库（扣库存）→ 同步金蝶 `SAL_OUTSTOCK` |
| 约束落地 | 库存不足 / 库位异常 / 设备故障 → `异常待人工` + 站内告警；复核不一致 → `复核异常` + 告警，改数量/重扫/放行后可继续；销售订单未同步金蝶 → 不阻断流转，确认出库时由操作员显式确认（`override_*` 留痕） |

## 6. 端到端实测（2026-10-21，后端 8081 / 前端 3100）

1. **CK-001 正常闭环**：`WORK00119` 无 PPBOM → 扫码返回 `warning`、`requirementSource=手工`；创建 `LL2112749001902977027`（PBC001×2）→ 分配（锁定 2）→ 下发 WCS（mock 受理）→ 模拟 `FINISHED` → 取料确认。结果：状态 `已完成`、`sync_status=同步成功`，库存 `8 → 6`，`locked_qty 2 → 0`。
2. **CK-002 正常闭环**：`XS-E2E-1021A`（客户 `01.001`，FG001×2）创建后 `sale_sync_status=同步成功`；分配取料箱 `BOX-E2E-001`（锁定 2）→ 下发 RMS（mock）→ `FINISHED` → 复核一致 → 确认出库。库存 `5 → 3`，分配行 `actual_qty=2`，状态 `已完成`。
3. **复核不一致**：首次复核传错误扫描码 → 返回「复核不一致，请改数量/重扫或填写原因放行」，单据转 `复核异常`，写入告警 `WMS出库复核不一致告警`；重扫 `BOX-E2E-001` 后复核通过。
4. **销售订单未同步 override**：`XS-E2E-1021B` 复核通过后将 `sale_sync_status` 置为 `同步失败`。确认出库返回 `needSaleOrderConfirm=true` 且**不扣库存**（`locked_qty` 保持 1）；带 `overrideSaleOrderSync=true` 与原因此后成功出库，`override_by=admin`、`override_reason` 已留痕，库存 `3 → 2`。
5. **库存不足**：`PBC001` 需求 9999 → 分配报「库存不足：PBC001 需求 9999，可用 11」，单据转 `异常待人工`，告警 `WMS出库库存不足告警`，**无残留锁定**（事务回滚）。
6. **关单**：分配后关单 → `已关闭`，`close_reason` 记录，`locked_qty 1 → 0`。
7. **前端**：出库管理菜单可见；列表 7 行含两类单据；详情抽屉展示主表/需求/分配与任务；新建领料弹窗扫码后显示工单信息、警告与手工添加明细入口（截图 `01`–`05`）。

> 本次发现并修复的缺陷：确认出库时未传实收数量，`actual_qty` 停留在分配时的占位 0，导致**订单标记已完成但库存未扣减、锁定被全部释放**（E2E 实测 quantity 8→8）。已改为「未复核且未传实收 → 按分配数量扣减；并回写分配行实收数量」，新增 2 个回归用例。

## 7. 已知限制 / 上线前动作

1. **金蝶当前未启用**（`KINGDEE_ERP_ENABLED=false`）：三个 Writer 均已实现并有单测，但 E2E 走的是 mock 成功，返回文案「已同步金蝶」在 mock 下会误导操作员。上线前需配置金蝶测试凭据做真实单据验证（`PRD_PickMtrl`/`SAL_SaleOrder`/`SAL_OUTSTOCK`），验证后清理测试单据。
2. **WCS/RMS 出库地址为空**：下发为 mock 受理；对接时配置 `wms.sync.wcs.outbound-url`、`wms.sync.rms.outbound-stations`。
3. **容器盘点/数据迁移不在本期**：敏捷仓按料箱出库要求 `wms_inventory.container_code` 非空；存量行需在上线前完成一次容器盘点/数据迁移（见项目记忆 `ck-outbound-container-inventory-migration`）。本次 E2E 以手工补 `container_code` 验证逻辑。
4. `PRD_PPBOM` 取不到（工单未下料或未匹配）时按设计降级为手工录入，页面已提示；生产环境应确认工单在库系统已审核并下料。
5. 手工重同步未做乐观认领（与 Quartz 同时触发时依赖金蝶单号幂等吸收）。

## 8. 最终评审修复（2026-10-21 复审后）

整支改动经独立评审，修复以下问题（均有单测或 E2E 复核）：

| 级别 | 问题 | 修复 |
| --- | --- | --- |
| Critical | 采购上架/生产不良品入库 upsert 未给 `container_code`（NOT NULL）→ 真实 SQL 报 1048 | 两处显式 `setContainerCode("")`；真实调生产入库不良品提交成功，库存行 `container_code=''` |
| Critical | 详情抽屉实收默认取 `actualQty`（分配占位 0）→ UI 确认零扣减 | 默认回落到分配数量；UI 点击「取料确认」实测默认 1.000、库存 6→5、`actual_qty=1` |
| Critical | 重新分配/双击分配会重复锁定、确认时双倍扣减 | 分配前条件认领状态 + 清理旧分配（释放锁定、删除旧行、复位明细）；实测异常待人工重分配后锁定仍为 2、有效分配行 1 条 |
| Critical | `confirm`/`close` 无事务，部分成功无法回滚 | 两个入口加 `@Transactional(rollbackFor=Exception.class)`；`onTaskFeedback` 同样加事务 |
| Critical | 关单跳过已完成任务 → 锁定与库位泄漏 | 关单一律释放锁定/库位；已完成未确认的单据额外 warn 提示人工盘点（实测锁定 2→0） |
| Important | 迟到的 RUNNING/FAILED 回执把已完成/已关闭单据拉回 | 回执状态迁移加来源白名单（条件更新），失败告警仅在迁移成功时发送 |
| Important | 实收数量未校验非负；`releaseLocked` 的 GREATEST 会清掉别单锁定 | 负数量直接拒绝；释放改为 `locked_qty >= qty` 条件更新 |
| Important | 生产组织解析静默回退默认组织 | 查不到返回 null 由 Writer 明确失败；物料跨组织不再退回第一条 |
| Important | 销售同步补偿会重试已关闭单据 | 候选与认领均加 `status <> '已关闭'` |
| Important | UI 在异常待人工不能重新下发 | 列表与抽屉的「下发」在该状态可用 |
| Important | 关单先放锁后取消设备任务 | 控制器改为先取消任务（尽力而为）再关单 |

Minor 也已全部处理：

| 问题 | 修复 |
| --- | --- |
| 后台同步连续失败不告警 | 新增 `sale_sync_fail_count`（Flyway `V3.9.5_18`，success=1）；出库/销售同步连续失败恰好 3 次时补偿任务补发一次告警（成功清零） |
| `resyncSale` 未校验单据类型 | 非销售出库单直接返回「仅销售出库单可同步销售订单」 |
| 「未配置地址按模拟受理」写进 `task_error` | WCS/RMS 受理成功不再写失败原因（实测 `task_error` 为空） |
| WCS 下发无退避重试 | 与 RMS 一致：3 次退避重试，仅可重试错误才重试 |
| 客户内码未按组织过滤 | `BD_Customer` 查询追加 `FUseOrgId.FNumber` 过滤 |
| mock 同步文案误导 | `WmsOrderSyncAttempt` 增加 `mocked` 透传，页面文案改为「已模拟同步（未启用金蝶）」 |

## 9. Rulings（执行期决策）

- `persistSaleSyncResult` 使用三参（id/status/error）：表无销售同步重试计数字段。
- 手工重同步不做乐观认领：金蝶 Writer 以单号幂等。
- Task 10 先建只读详情抽屉保证可编译，Task 11 补全交互。
- 视觉验证并入 Task 12 端到端。
- 确认出库默认实收数量的语义：仅对「未复核且未传实收」按分配数量处理，复核后显式 0 仍走「不扣减仅释放」。
