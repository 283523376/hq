# 单据打印模块（DY-001）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 WMS 内实现单据打印工作台：7 类定稿单据（盘盈/盘亏/其他出库/其他入库/委外领料/销售出库/销售退货）按客户样单版式打印，5 类样式待定置灰。

**Architecture:** 后端 `print` 包——快照表（金蝶来源 6 类）+ 金蝶只读 Reader（ExecuteBillQuery，FDocumentStatus='C'）+ 统一 VO 组装器（后端切段分页）+ 编排服务（本地入口解析、金蝶失败回退快照）；前端打印工作台（12 页签）+ 6 个模板组件（预览即打印视图，A4 横向）。

**Tech Stack:** Spring Boot 4 / MyBatis-Plus / Flyway（后端）；Vue 3 + Ant Design Vue（Vben fork，defHttp）（前端）；金蝶云星空 WebAPI（只读）。

**Spec:** `docs/superpowers/specs/2026-11-09-yx-wms-单据打印模块-design.md`（实现与验收均以 spec 为准；样式源 `资料\需要打印的单据\`）。

## Review Focus

1. **未审核单据被打印**（业务风险最高）→ 期望「单据不存在或未审核，不能打印」；pin：Task 2 步骤断言 filter 含 `FDocumentStatus='C'`。
2. **金蝶故障时静默打出旧快照且无标注** → 期望预览页显著标注数据时间；pin：Task 4 断言回退时 `snapshotTime` 非空 + Task 6 预览页标注条。
3. **未回写的盘点单被当成可打印** → 期望「该盘点单未回写金蝶，暂无盘盈/盘亏单可打印」；pin：Task 4 入口解析测试。
4. **多页单据合计重复/页码错** → 期望合计只在末页、每页重复表头、`共y页` 正确；pin：Task 3 分页测试（>rowsPerPage 行数）。
5. **查询入参带单引号破坏金蝶 filter** → 期望与既有 Reader 同款转义；pin：Task 2 转义测试。

```java
    List<Map<String,String>> localBills(String billType, String keyword); // 下拉：billNo/label/printable
}
```
- 编排规则（全部可测）：
  1. `PROFIT/LOSS`：入参 PD… → 查盘点单（不存在报错）→ `erpBillNo` 逗号拆分按前缀 QTRK/QTCK 取对应单号（无 → `该盘点单未回写金蝶，暂无盘盈/盘亏单可打印`）→ 金蝶链路；入参 QTRK…/QTCK… 直接金蝶链路（类型与前缀不匹配报「单据类型与单号不匹配」）。
  2. 金蝶链路：`reader.isEnabled()==false` → 有快照走快照（`snapshotTime` 标注）、无快照报「金蝶同步未启用…」；`queryApproved` 成功 → 组装 + `store.upsert`（payload=金蝶行 JSON）；抛异常/查空 → 有快照回退组装（`snapshotTime` 标注）+ 金蝶失败原因放入 extras.warn；无快照报「单据不存在或未审核，不能打印」（查空）或「金蝶查询失败：…」（异常）。
  3. `SALES_OUTSTOCK`：入参 XS… 本地单 → 本地明细组装为底 → `erpBillNo` 非空则查金蝶补价税/规格（失败→仅本地 + extras.warn）；入参 XSCK…（本地查无）→ 直接金蝶链路（同 2 的回退规则，但无快照兜底成功时也 upsert）。
  4. 其余 4 类（MISC_DELIVERY/MISC_INSTOCK/SUB_PICK/SALES_RETURN）：金蝶链路（同 2）。
  5. `localBills`：PROFIT/LOSS → 盘点单（`erp_bill_no` 非空，按 stocktakeNo 模糊）；SALES_OUTSTOCK → 销售出库单（按 outboundNo 模糊）；其余类型返回空列表。

## 缺陷记录（2026-11-10 客户验收后发现）

### 缺陷 1：批量打印分页失效，多张单据只输出一页

- **现象**：工作台勾选多张单据 → 批量打印 → 无论「每张一页 / 自动排版」哪一档，都只打出一页。
- **误判方向**：起初怀疑 `print.css` 里 `.print-area { position: absolute }`（绝对定位盒子不跨页）。
  **实测排除**——仅去掉绝对定位仍是 1 页。
- **真因**：全局样式 `src/design/index.less:16` 的 `html { overflow: hidden }` 与 `:21-24` 的
  `html, body { height: 100% }`。打印媒体下根元素被裁到第一屏高度（`documentElement.scrollHeight`
  = 1050 = 视口高，而 `body.scrollHeight` = 2124），超出部分直接丢弃。`break-after: page` 本身
  一直生效（计算值实测为 `page`），只是内容根本没流到第二页。
- **修复**：`print.css` 的 `@media print` 内放开 `html, body { height: auto !important; overflow: visible !important }`。
  实测对照：仅这一条即 1 页 → 3 页；单独改 `height: auto` 无效，`overflow: visible` 是生效项，两条一起写覆盖其它浏览器。
  `!important` 必须加：`design/index.less` 走全局入口、`print.css` 在组件内 import，构建后插入顺序不保证。
- **顺带影响**：这是平台级隐患，其它页面打印同样会被裁成一页，此修复只在本模块加载后生效（不影响别处）。

### 缺陷 2：客户口径「分页要保留完整单据，不把同一张单据分到两页」

- **实现**：`@media print` 内给 `.print-item:not(.multi-page)`、`.print-page`、`.sheet-table tr`
  加 `break-inside: avoid`，剩余空间不够就整张挪到下一页。
- **例外**：行数超过单页容量（组装器按 12 行/页，销售出库/销售退货/其他入库 6 行/页）时，
  单据本身就是多页，由组装器决定分页，故 `PrintPreview.vue` 给这类单据打 `.multi-page` 标记放行。
- **注**：`break-inside: avoid` 是提示而非硬约束，整块在空白页上也放不下时浏览器仍会回退为拆分，不会裁掉内容。
