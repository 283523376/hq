## 1. 为什么需要这张表

金蝶按 **物料分组（FMaterialGroup）** 分类，共 **2996 个分组**，语义是**材质 + 工艺**：

| 分组编码 | 分组名称 | 物料数 | 物料样例 |
| --- | --- | --- | --- |
| PJ.1301.0202.C | 五金部件 | 1587 | 大头六角螺丝 / 五金组件设备类 |
| XA.00.01010101 | 自制 | 1118 | 非涂层-整支-鱼尾型-双右旋*密齿-自制 |
| W.X.001 | 钻针段差精磨 | 545 | 整体ST0.2*4.0 |
| 75 | 低值易耗品 | 317 | 工业酒精 |
| A.C1.1.Y75 | Y75材质 | 238 | 硬质合金立铣刀 |

而 WMS 需要的是**仓储路由分类**：`原材料 / 半成品 / 成品 / 辅料`（决定进立库还是线边仓）。
**两套体系互不对应**——这就是为什么物料同步永远填不上 `category_id`：ERP 里没有 WMS 的这套分类。

## 5. 怎么用

1. 打开 `2026-11-05-yx-wms-物料分组映射表.csv`（Excel）
2. 只看「业务确认」列，填 `原材料` / `半成品` / `成品` / `辅料` 之一
   - 「建议WMS分类」列已自动标好的，确认无误可留空（表示采纳建议）
   - 「标注依据」列说明为什么这么标
3. 建议按「物料数」降序处理——**标完前 631 组就覆盖 80% 物料**，不必逐条看完 2996 行
4. 标注完成后回传，我据此：
   - 在 `wms_material_category` 里按分组建分类树（复用已有 `erp_group_number`/`erp_group_name` 字段）
   - 物料同步时按 `FMaterialGroup.FNumber` 自动挂接 `category_id`
   - 未在表内的新分组走兜底规则（可配置）

## 6. 一个前置判断（需要业务确认）

WMS 的「原材料 / 半成品 / 成品 / 辅料」是否还需要**四类**？

- 若只需要「立库 / 线边仓」两档，映射表可以简化成二选一
- 若保留四类，则「成品」与「半成品」的界线要明确——本项目已有决策：
  **产品类型由入库来源决定**（半成品=工序汇报、成品=完工入库），
  那么物料分类与实际产品类型**可能不一致**，需要说清以哪个为准
