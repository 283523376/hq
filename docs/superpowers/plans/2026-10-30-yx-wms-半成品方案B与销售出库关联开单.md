# 半成品方案 B 落地 + SAL_OUTSTOCK 关联开单 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ①销售出库回写改为**关联开单**（SAL_OUTSTOCK 通过 Link 结构绑定发货通知单，可部分数量）；②工序汇报草稿补「推进」入口，走方案 B（WMS 记账不回写开单，按 FSrcBillNo 对账回填 ERP 单号）。

**Architecture:** 出库回写器按 `source_bill_no` 分支——通知单来源的出库单走「查通知单分录 → Link-Save → Submit」；手工销售单保持原直开路径。半成品入库按 `erp_entry_key` 识别「工序汇报来源」：推进后不进回写队列（`sync_status=无需同步`），由同步重试任务按 `FSrcBillNo=GXHB单号` 定期对账回填 ERP 生产入库单号。

**Tech Stack:** Spring Boot 4.1 / MyBatis-Plus / JUnit5+Mockito / Vue3+ant-design-vue；金蝶 WebAPI（Save-with-Link、ExecuteBillQuery）。

**Spec:** `docs/superpowers/plans/2026-10-30-yx-wms-出库链路端到端验证报告.md` §8（两条路实测与选型）；用户 2026-10-30 拍板：选方案 B，stock-map 先修关联开单再配置。

## Global Constraints

- 凭据仅服务端：`KINGDEE_ERP_*` 环境变量注入，日志脱敏，不入仓库（[[kingdee-erp-credentials]]）。
- 单号以金蝶为准：不传 `FBillNo`，回存 ERP 单号到 `erp_bill_no`（[[erp-source-of-truth-bill-number]]）。
- 所有接口统一 `Result<T>`；删除/同步失败文案逐字透出；禁魔法值（常量进 `WmsConstants`）。
- 构建/测试一律 `bash /d/tools/m.sh -P dev …`；改完 wms 模块必须 `install` + 重启后端（[[jeecgboot-build-command]]、[[yongxin-wms-dev-runtime]]）。
- 单测命令带 `-Dsurefire.failIfNoSpecifiedTests=false`；批量删测数据前先备份。
- 金蝶报文铁律（本会话实测）：基础资料引用用 `{"FNumber":…}`；单值子实体传字典不传数组；**流程/基础对象用 `{"FID": GUID}` 字典**；Link 子结构键名带 `F<Entity>_Link_` 前缀。

## Review Focus

1. **同一通知单两张 WMS 单先后同步**（草稿期重复开单）：期望第二张报「已存在未审核出库单 XSCK…，请先处理」而不是又开一张。→ Task 1 测试 `write_existingUnapprovedDraft_failsReadable`。
2. **明细物料在通知单上找不到分录**（同步落后/多组织物料）：期望失败文案含通知单号+物料编码。→ Task 1 `write_materialMissingOnNotice_failsReadable`。
3. **remain 已被别单占用**（并发/已提交未审）：期望不覆盖、报错可读。→ Task 1 `write_noticeRemainInsufficient_failsReadable`。
4. **汇报来源入库被误回写**（551 张存量草稿推进后）：期望永不 push PRD_INSTOCK、`erp_bill_no` 停留 GXHB 单号直到 ERP 侧真入库。→ Task 5 `reconcile_*` 系列测试。
5. **推进错状态**（非草稿被推进/无载具）：期望条件认领只成功一次、重复点击幂等。→ Task 4 `promote_*` 测试。
