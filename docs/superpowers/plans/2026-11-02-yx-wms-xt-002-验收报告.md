## 4. 未跑通 / 已知限制（必须知情，2026-11-02 整改后复核）

1. **金蝶作废链路：真账套实测完成，结论是「测试账套造不出作废样本」**（2026-11-02 补跑）。

   已按 `KINGDEE_ERP_*` 环境变量带真实凭据重启后端并连通金蝶（工单同步成功）。
   随后逐条尝试作废，**全部被金蝶业务流拦截**：

   | 尝试 | 金蝶返回 |
   | --- | --- |
   | 直接 `Cancel` 已审核单（`MO1012615492` 等，`FDocumentStatus=C`） | 单据状态为创建或重新审核的数据才允许作废 |
   | 先 `UnAudit` 再 `Cancel`（`MO1012600001`，C） | 分录业务状态为「计划确认」「计划」时允许反审核 + **单据已存在关联的下游单据，不能反审核** |
   | 直接 `Cancel` 未审核单（`MO1012603866`，`FDocumentStatus=A`） | **单据已存在关联的下游单据，不能作废** |
   | 全账套查 `FCancelStatus='B'`（101 / 100 / 不限组织） | **0 条**（账套里从未有作废工单） |

   **根因**：101 组织的 `PRD_MO` 保存后即存在关联下游数据（工序计划/用料清单），
   金蝶不允许作废；新建工单同样被卡在「工艺路线不能为空 + 无法配齐分录必填」，也无法绕开。

   **因此「ERP 作废 → 同步进 WMS → 状态变已作废」在本测试账套无法端到端验证**，
   只能靠单测（`gateStatus_cancelled_returnsCancelled`、`syncWindow_usesModifyDate`、
   `sync_cancelledOrder_bypassesMaterialAndLotGates`、`statusRank_cancelledIsTerminal`）。
   要真机验证，需要金蝶顾问在测试账套造一张**可作废**的工单，或临时关闭该组织的下游联动。

   顺带验证到的真账套事实（本次补跑的实证）：
   - **ERP 同步通道在真账套下确实留痕**：`wms_audit_log` 出现
     `工单 / MO1012603866 / 同步落地 / ERP同步 / 成功 / system`，`after_value` 带完整落库字段；
   - **二次同步的 before/after 正确**：`MO1012615492` 一条记录里 `before_value` 是 WMS 原状态；
   - **影响面接口对真实工单可用**：`/wms/audit/impact?workOrderNo=MO1012603866` 返回工单 + 1 条时间线；
   - **实测踩出并修复一个缺陷**：`diff_fields` 把金蝶的 `2000.000` 与 WMS 的 `2000.0`
     判成变更（按字符串比较），已改为 `BigDecimal.compareTo` 并加 2 例单测。
2. **作废是终态，不可自动回退**：ERP 撤销作废（`FCancelStatus` 回到 `A`）后 WMS 仍停在「已作废」
   （`statusRank=4` 最高）。恢复需人工 SQL，见 §5。
3. **UI 动作的单号靠切面回查**（评审 I2，已整改）：出库/调拨端点入参只有行主键，
   切面检测到 19 位 id 时回查单据换成业务单号、工单号进 biz_ref；单据已删除时回查失败，
   记录保留 id（此时按单号搜不到这一条，但同步/回写记录仍带单号串链路）。
   每次审计多一次按主键的回查，属低频操作可接受。
4. **影响面按「物料+批次」近似关联库存**，无法精确归属到某张单据（设计 §6 已声明）。
5. 历史时点结存未做：影响面展示的是**当前**库存。
