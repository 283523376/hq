## 3. 发现并修复的缺陷（验收过程中暴露）

1. **切面把失败记成成功**：控制器普遍 `try/catch → Result.error(...)`，方法本身正常返回。
   已在切面中判 `Result.isSuccess()`，失败时记「失败」并带出 `message`；新增 2 例单测钉住。
2. **导出文件名错位**：审计导出产出 `库存台账_*.xlsx`。已按 taskType 分前缀（`审计日志_` / `库存台账_`）。

## 4. 未跑通 / 已知限制（必须知情）

1. **金蝶作废链路未做真账套实测**：本次后端启动时未加载金蝶连接配置
   （`KINGDEE_ERP_BASE_URL` 等环境变量为空），调用返回「URI is not absolute」，
   因此「ERP 作废 → 同步进 WMS → 状态变已作废」这一步**没有真机验证**，
   只有单测（`gateStatus_cancelled_returnsCancelled`、`syncWindow_usesModifyDate`、
   `sync_cancelledOrder_writesCancelledStatus`、`statusRank_cancelledIsTerminal`）。
   需要在配好凭据的环境再跑一次。
2. **作废是终态，不可自动回退**：ERP 撤销作废（`FCancelStatus` 回到 `A`）后 WMS 仍停在「已作废」
   （`statusRank=4` 最高）。恢复需人工 SQL，见 §5。
3. **HTTP 通道的 biz_no 是行主键**：出库/调拨端点的路径参数只有 `id`，所以这些审计记录的
   `biz_no` 是内部主键，不是单号。按单号反查这些动作时，靠同步/回写记录（它们带单号）串链路。
   若要按单号反查纯 UI 动作，需在这类端点里先查单据再显式 `record`（后续可做）。
4. **影响面按「物料+批次」近似关联库存**，无法精确归属到某张单据（设计 §6 已声明）。
5. 历史时点结存未做：影响面展示的是**当前**库存。
