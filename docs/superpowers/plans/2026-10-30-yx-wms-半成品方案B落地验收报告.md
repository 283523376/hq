  WMS 的仓库只影响自家记账。这条决定了 stock-map 的真实语义，配置前需业务确认

### 1.2 方案 B：工序汇报通道

| 项 | 内容 |
| --- | --- |
| 推进入口 | `POST /wms/production/{id}/promote`（载具码必填 ≤64）：草稿 → 待上架，占立库位、生成 WCS 任务、`sync_status=无需同步`；条件认领防重复 |
| 回写豁免 | `WmsKingdeeInboundWriterImpl.write()` 首行：`erp_entry_key` 非空 → 只对账不开单 |
| 对账回填 | 按 `FSrcBillNo=GXHB单号` 回查 `PRD_INSTOCK`，命中 B/C → 回填真实 SCRK 单号；未命中 → 可读失败「ERP 尚未汇报入库」 |
| 定时对账 | 生产入库补偿任务步骤⑤，未命中不计失败不告警 |
| 前端 | 生产入库页草稿行「推进」按钮（Modal 录载具码） |

  `erp_bill_no` 保持 `GXHB659871`、**金蝶未产生重复入库单** ✅
- 回退过程中发现并修复：`claimFinished` 曾把 `sync_status` 无条件刷成「待同步」，
  把方案 B 的单据塞进同步队列（详见 §3）

## 4.1 独立评审后的加固（2026-10-30，commit `694ba732`）

全量 diff 交给独立评审（最能力模型）复查，发现并修复 1 个 Critical + 5 个 Important：

| # | 问题 | 修复 |
| --- | --- | --- |
| C1 | 通知单**同物料多分录**被当成一条：只建一条索引 + 逐行比余量 → 误报「剩余不足」，或多条明细绑同一分录超额核销 | 按物料索引**分录列表**，出库量按分录余量顺序切分（一条明细可拆多条金蝶分录），余量分配时递减 |
| I1 | 「转人工完成」把方案 B 单据重新塞回回写队列（claimFinished 修了这里漏了） | 按 `erp_entry_key` 区分，汇报来源保持「无需同步」 |

| I5 | 缺口计算对同物料多行**重复扣减** ERP 已关联量 | 改为逐行递减消耗 |
| T | 两处测试失真：我覆盖掉了 `WmsSalesDemandServiceImplTest` 原有 6 个用例；job 闸门用例 stub 错方法（靠 mock 默认值假绿） | 恢复原用例；改 stub 并加 `verify` 自证 |
