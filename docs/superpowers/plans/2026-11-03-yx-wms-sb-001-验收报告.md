## 3. 未完成 / 已知偏差

### 3.1 真账套对账未执行（阻塞在数据）

本机 `wms_inventory` 仅剩 2 行且 `quantity=0`（2026-10-30 测试数据清理所致），因此：

- 对账快照为空，无法与金蝶即时库存产生有意义的比对结果；
- 计划 §Task12「成品区（D.01/F.03）应为 0 差异」**未验证**；
- 根因是已知产品缺口：**WMS 无「从零造库存」入口**（采购入库已停用、盘点要求先有账面）。

**下一步**：现场产生真实生产入库后，带 `KINGDEE_ERP_ENABLED=true` 重启，跑一次 FULL，核对成品区差异为 0。

### 3.2 「跳转到盘点单详情」降级

spec §2.8 第 5 步要求发起盘点后跳转盘点单详情。盘点模块当前只有列表页、无详情路由，实现降级为「提示盘点单号 + 引导去盘点页」。属已知偏差，待盘点模块补详情页后恢复。

### 3.3 前端未做浏览器冒烟

`eslint` 0 error、`vite build` 通过、`tsc --noEmit` 对 `views/wms/sync` 0 error；但本 checkout 的 `vue-tsc@1.8.27` 与 `TypeScript 5.9.3` 不兼容（既有工具链问题），模板级类型检查与真实点击未做。导出链路按 Content-Disposition 判成败的逻辑已由代码审查确认，仍建议上线前点一次。

### 3.4 其他已知限制（记录备查）

- `wms_sync_log.create_by` 固定写 `system`（既有设计），**操作人看 `wms_sync_run.operator` 与审计表**。
- 对账快照为空时短路批次不写 `wms_sync_log`，仅应用日志 INFO。
- WAREHOUSE 批次：所选仓库中「有账的仓」会查，「无账的仓」只有整体为空时才回退；部分为空时不会发现该仓的 ERP 单边库存。
- 差异清单 `diff_qty` 为 NOT NULL，所有「仅WMS」行记 `erpQty=0/diffQty=wms`（不写 null）。
- 保留期：日志 90 天、批次/快照/流水 180 天、差异 365 天；180~365 天区间差异行可能指向已删批次。
