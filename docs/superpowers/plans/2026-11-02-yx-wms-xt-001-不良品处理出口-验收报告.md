## 2. 真实环境验证（2026-11-02，8081 + yongxin_wms）

前置：造了一条废品仓库存（物料 `2409010003`、批次 `XT001-TEST`、库位 `FPC-DEFAULT`、数量 10）。

| 验证项 | 结果 |
| --- | --- |
| 台账接口 | `total=1`，只显示废品仓那一行，可报废数量 10 |
| 报废 3 件 | `200 报废成功`，单号 `BF2117170577532600321`，`remainingQty=7` |
| 库存变化 | 10 → **7** ✅ |
| 出库单 | `outbound_type=报废出库`、`status=已完成`、`remark=XT-001 验证报废` |
| 出库明细 | 含物料快照（code/name/unit）+ 批次 + 数量 |
| 超量报废 | `500 报废数量超过可用数量（可用 7）`，**库存不变** ✅ |
| 审计留痕 | `action=作废`，成功/失败各一条 |

**过程中修掉一个缺陷**：首次报废报 `Field 'material_code' doesn't have a default value`——
出库明细只写了 `materialId`，没写物料快照。修复时确认了**事务边界是对的**：
报错后库存仍是 10，没有留下「单建了但库存没扣」的半成品。

## 3.5 混合单不良品回写 真账套验证 ✅（2026-11-02 补做）

**背景**：金蝶 `PRD_INSTOCK` 只有良品数量字段，混合单（良品>0 且不良品>0）过去只回写良品，
不良品在 ERP 账上漏记。已改为额外开其他入库单。

**验证过程**：提交混合入库单（工单 `MO1012615492`，良品 10 + 不良品 2）→ 转人工完成触发回写。

| 单据 | 单号 | 状态 | 仓库 | 数量 |
| --- | --- | --- | --- | --- |
| 生产入库 | `SCRK101261100004` | B（已提交） | D.01 | **10** |
| 其他入库 | `QTRK10126110001` | B（已提交） | **F.03**（废品仓） | **2** |

数量、仓库、物料全部对上——良品进 D.01，不良品进废品仓，**ERP 账不再漏记**。

**过程中发现并修复的配置缺失**（commit `6e4b12e3`）：
`stock-code-by-org` 的 `"101"` 块只配了 `stereo`/`agile`，**漏了 `scrap`**。
代码在「按组织覆盖表存在」时不会回落通用 `stock-code.scrap`，于是报
「组织[101]未配置不良品仓库」。这是生产也会踩的坑：101 一旦录混合单，不良品就写不进金蝶。
已补 `scrap: "F.03"`。

## 4. 测试数据清理 SQL

本次在废品仓造了一条测试库存并报废了一部分，需清理：

```sql
-- 报废单与明细
DELETE d FROM wms_outbound_detail d
  JOIN wms_outbound_order o ON d.outbound_id = o.id
 WHERE o.outbound_type = '报废出库' AND o.remark LIKE 'XT-001%';
DELETE FROM wms_outbound_order WHERE outbound_type = '报废出库' AND remark LIKE 'XT-001%';

-- 测试库存行
DELETE FROM wms_inventory WHERE id = 'XT001TESTINV0001';

-- 相关审计行
DELETE FROM wms_audit_log WHERE biz_no LIKE 'BF%' OR biz_no = 'XT001TESTINV0001';
```
