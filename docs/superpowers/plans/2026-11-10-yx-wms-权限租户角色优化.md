# WMS 权限/租户/角色优化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落地已确认的 RBAC 设计：5 个业务角色 + 权限矩阵（V3.9.5_54 数据脚本）、admin 缺口修复、租户脏数据治理、权限三方对齐检查脚本、5 角色登录验收。

**Architecture:** 零代码改动——全部走 Flyway 数据迁移（幂等、固定 id、附回滚注释）+ 一个只读检查脚本 + 数据治理 UPDATE。前端 BACK 权限模式自动生效，无需前端改动。

**Tech Stack:** MySQL 8（`WITH RECURSIVE` CTE 做菜单子树展开）/ Flyway / Python 3（检查脚本，经 mysql.exe 子进程查库）/ Playwright（登录验收）。

**Spec:** `docs/superpowers/specs/2026-11-10-yx-wms-权限租户角色优化-design.md`（矩阵 = §3.2，治理 = §3.1，防坑 = §3.3；本计划不重新设计，口径冲突以 spec 为准）

## Global Constraints

- **平台代码零修改**：`jeecg-module-system`、`jeecg-boot-base-core` 及其余后端 Java、前端 Vue 均不改。
- **只新增一个迁移** `V3.9.5_54__wms_rbac_roles.sql`；不改已执行的 52/53。
- **幂等**：全部 `INSERT IGNORE` / 带 `WHERE ... <> 目标值` 的 UPDATE / 左连接 DELETE，重复执行无副作用；文件末尾附注释形式的回滚段。
- 写法惯例先看 `V3.9.5_53__wms_print_menu_fix.sql`（列名、id 生成方式、注释风格），与其保持一致。
- 角色固定 id：`191000000000009001~905`，`tenant_id=0`；admin 角色 id `f6817f48af4fb3af11b9e8bf182f618b`。
- SQL 文件 UTF-8 编码；mysql.exe 一律带 `--default-character-set=utf8mb4`。
- 后端起停走 `tmp_files/.tmp_env/`（`start-backend.sh` 已含金蝶 env 与 8081；`m.sh` 是 Maven 包装器）。
- 权限矩阵口径（唯一事实源 = spec §3.2）：admin=108 全量；manager=88；operator=30；stocktake=6；viewer=8（按钮码计数，菜单另计）。

## Review Focus

1. **重复执行**（Flyway 重跑/手工直接执行两遍）：幂等必须成立——同一文件直接跑两遍，`sys_role`/`sys_role_permission` 行数不变。→ Task 1 断言脚本含「跑两遍行数不变」检查，Task 3 执行。
2. **admin 登录回归**（改 `login_tenant_id=0` + 停演示租户后 admin 是否仍能登录、菜单不受损）：Task 3 迁移后立即 UI 冒烟。若登录页仍弹演示租户选择，回退动作用 `del_flag=1`（回滚注释里写明）。
3. **业务角色的菜单树边界**（业务角色只见 WMS 子树、演示菜单不可见、按钮随 perms 隐藏）：Task 4 按矩阵逐账号 Playwright 断言，含「不该见的目录必须不存在」。
