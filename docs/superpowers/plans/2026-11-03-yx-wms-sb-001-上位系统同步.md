# SB-001 上位系统数据同步 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现 WMS→金蝶库存/流水对账：范围配置、汇总落快照、拉金蝶即时库存比对、差异清单（可发起盘点）、全程日志与保留期清理。

**Architecture:** 新增 4 张 `wms_sync_*` 表承载「批次/快照/流水/差异」；汇总与比对逻辑放在纯静态比较器 + 聚合 SQL；金蝶侧走新 Reader（`STK_Inventory` 分页查询）接口化以便 mock；执行走单线程池异步 + 每日 23:00 定时任务（水位线窗口）；差异发起盘点复用既有 `IWmsStocktakeService.create`（草稿）。

**Tech Stack:** Spring Boot 4 / MyBatis-Plus / Quartz（自注册）/ Flyway / AutoPoi / Vue 3 + Ant Design Vue（Vben）。

**Spec:** `docs/superpowers/specs/2026-11-03-yx-wms-sb-001-上位系统同步-design.md`（本计划所有口径以它为准；冲突时以 spec 为准并回报）。

## Global Constraints

- 所有 Maven 命令走 `bash /d/tools/m.sh -P dev ...`（mvn 不在 PATH）；单测模块 `-pl jeecg-boot-module/jeecg-boot-module-wms`。
- 提交约定：Conventional Commits `feat(wms): …`，从 `D:\yongxin-WMS\JeecgBoot` 仓库根提交。
- 项目**没有 MetaObjectHandler**：审计字段一律 `WmsUtils.fillCreate/fillUpdate` 显式写入；异步线程先取好 `operator` 再传参（线程内无 Shiro 上下文）。
- 接口统一 `Result<T>`；写端点必须 `@RequiresPermissions` + try/catch `Result.error(e.getMessage())`；DTO 的 Date 字段必须 `@DateTimeFormat`。
- 状态/类型一律中文常量进 `WmsConstants`，禁止魔法值；配置项加在 `WmsConfigKey` 枚举。
- 金蝶查询：`FBaseQty`（不是 `FQty`）；翻页 `TopRowCount=0` + `Limit` + `StartRow`；组织固定 `FStockOrgId.FNumber='101'`。
- 重试口径（spec §2.6 的落地解释）：**首次尝试 + 最多 3 次重试（共 4 次尝试）**，退避 1s/2s/4s；每次失败尝试写一条 `wms_sync_log`（retryCount=1..3）；3 次重试仍失败 → 批次置失败 + 告警。退避数组做成包级可注入常量，单测置 0。
- 比对 Key = `仓库编码 + 物料编码 + 批次号`，批号 null/空串统一归一为 `""`；数量比较只用 `BigDecimal.compareTo`。
- 权限码固定 5 个（spec §5）；快照/流水/批次查询端点归 `wms:sync:run`，日志归 `wms:sync:log:view`，差异页归 `wms:sync:diff:view`。
- 菜单/权限 ID 用 **1910000000000000951~0965 / 1920000000000000951~0966**（已核对空闲；`0951` 之前段已被占用）。

**SQL 口径（照抄，一次写对）：**

- 库存聚合（spec §2.3 原文）：

```sql
SELECT COALESCE(NULLIF(w.erp_stock_code,''), w.warehouse_code) AS erp_warehouse_code,
       w.warehouse_code,
       COALESCE(NULLIF(m.kingdee_code,''), '')  AS erp_material_code,
       m.material_code, m.material_name, m.unit,
       COALESCE(i.batch_no, '') AS batch_no,
       SUM(i.quantity) AS qty, SUM(i.locked_qty) AS locked_qty
FROM wms_inventory i
JOIN wms_location  l ON l.id = i.location_id
JOIN wms_warehouse w ON w.id = l.warehouse_id
JOIN wms_material  m ON m.id = i.material_id
WHERE i.quantity <> 0
  <if test="windowStart != null">AND i.update_time &gt;= #{windowStart}</if>
  <if test="warehouseCodes != null">AND w.warehouse_code IN
    <foreach collection="warehouseCodes" item="c" open="(" separator="," close=")">#{c}</foreach></if>
GROUP BY erp_warehouse_code, w.warehouse_code, erp_material_code,
         m.material_code, m.material_name, m.unit, COALESCE(i.batch_no,'')
```

（MySQL `ONLY_FULL_GROUP_BY` 下 GROUP BY 里必须重复 COALESCE 表达式，不能只引别名——上面已这样写。）

- 生产入库：`wms_production_inbound` WHERE `status='已入库'`（常量名 `WmsConstants.PROD_STATUS_INBOUND`，SQL 里直接写字面量并加注释指向常量，本仓库 mapper xml 惯例如此）AND biz 窗口 `update_time` BETWEEN；良品行：`good_qty>0` 仓库走 `location_id`，不良品行：`bad_qty>0` 仓库走 `scrap_location_id`（LEFT JOIN，空→`''`）；两段 UNION ALL，direction 均 `'IN'`，`flow_type='生产入库'`，qty 取对应数量。
- 出库：主表 `wms_outbound_order`（status=`'已完成'`）JOIN `wms_outbound_detail` JOIN `wms_outbound_allocation`（`allocation.actual_qty>0`）JOIN `wms_location/wms_warehouse`——**出库单头没有仓库字段，仓库只能从分配行的 locationId 回溯**；qty=`allocation.actual_qty`，direction `'OUT'`，`flow_type='出库'`。
- 调拨：`wms_transfer_order`（status IN `'已完成','已调整'`）JOIN `wms_transfer_detail`，拆两行：调出（qty=`actual_qty`，仓库 `out_warehouse_code`，direction `'OUT'`）与调入（仓库 `in_warehouse_code`，direction `'IN'`），`flow_type='调拨'`。
- 盘点：`wms_stocktake_order`（status=`'已调整'`）JOIN `wms_stocktake_detail`，`diff_qty>0`→盘盈 IN、`diff_qty<0`→盘亏 OUT（qty 取绝对值），仓库走 `location_id` 回溯，`flow_type='盘点'`，时间取 `order.adjust_time`。

    - 行的 `materialCode` 为空（聚合层已把无 `kingdee_code` 物料的 `erp_material_code` 置 `''`）→ 直接 `matchStatus=仅WMS`，跳过 ERP 匹配；
    - 两边都有且 `compareTo==0` → `一致`；否则 `数量差异`，`diffQty=wms-erp`；
    - 仅 WMS → `仅WMS`；仅 ERP（key 在 erpByKey 且不在 snapshots）→ **由调用方**（Task 7）构造 erp 单边快照行后再进 `apply`，`apply` 本身不造行；
    - `detectErpOnly=false` 时调用方不得把 ERP 单边行放进 snapshots（约束写在 javadoc）。
- Consumes: `WmsSyncSnapshot`（Task 3）。

  - `1.0` vs `1.00` → 一致（Review Focus #1）；
