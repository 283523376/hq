## 2. 真机验证结论（以本次为准）

**已验证**

1. **下推能带出 BOM**：`Push(MO → PRD_INSTOCK, TargetBillTypeId=SCRKD01_SYS)` 成功生成草稿；
   保存该草稿**不再报「BOM版本不能为空」**，只剩「批号」「领料套数」两个正常业务前置
2. **拒绝路径**（WMS 新代码真机跑通）：对「生产汇报入库流程」的老工单，返回
   `…不在允许下推的范围[__empty__, 生产直接入库流程]。金蝶原文：业务流程字段的值，必须是如下值之一：空值, 生产直接入库流程。`
3. 下推的硬前置已摸清并写入配置注释：已审核 / 可直接入库单据类型 / **分录状态=开工** /
   入库上限有余 / **业务流程=空或生产直接入库流程** / 物料在入库组织允许库存

**未验证（明确遗留）**

- **WMS 全链路 e2e**（页面建单 → 手工同步 → 金蝶可查）：卡在领料前置。
  本账套**没有「生产订单 → 生产领料单」的转换规则**，无法用 API 造领料单；
  「执行至开工 / 反执行」的业务操作编码也调不通（试过 11 个常见编码均报「生产订单没有此接口」），
  只能人工点界面。用户决定**以当前验证为准**。
- 成品仍走原 Save 路径（未切换，已验证通过），`push-inbound-enabled=false` 可整体回滚。

## 3. 过程中新发现（已写入项目记忆）

1. **中文作为 Map 的 key 时 Spring 绑定会静默丢条目**（运行期只剩 `__empty__`），
   故流程映射改成列表结构（中文作「值」绑定可靠）
2. 金蝶 WebAPI 路径里 `ServicesStub` 后面是**点**不是斜杠，写错会返回误导性的「URL 不正确」
3. 已下达（FStatus=3）的生产订单不能直接反审核/删除，必须先在界面 `行执行 → 反执行`；
   `FStatus` 也不能通过 Save 直接改（报「分录业务状态已改变」）
