### 1.2 后端（`org.jeecg.modules.wms`）

| 接口 | 方法 | 权限 | 说明 |
| --- | --- | --- | --- |
| `/wms/inventoryLedger/page` | GET | ledger | 多条件分页；pageSize 上限 200；`total=0` 即空结果 |
| `/wms/inventoryLedger/export` | POST | export | 提交异步导出任务，返回 taskId；`@AutoLog 库存-台账导出` |
| `/wms/inventoryLedger/export/task/page` | GET | export | **只返回当前登录人**的任务 |
| `/wms/inventoryLedger/export/task/{id}/download` | GET | export | 归属校验 + 人话错误文案（JSON 回写） |
| `/wms/inventoryLedger/export/task/{id}/retry` | POST | export | 只允许 FAILED；重置后重新入队 |
| `/wms/inventoryLedger/export/task/{id}` | DELETE | export | 删记录 + 删文件；进行中不可删 |

关键实现：

- 查询 SQL 四表 join（inventory/material/location/warehouse），排序键 = `wms_inventory` 唯一键四列，
  分页与导出同序；导出用**游标分批**（无 OFFSET），每批 5000 行。
- 导出执行：专用线程池（核心/最大 2、队列 20，无 `@Async`）；`@Transactional(readOnly=true)` 一致性快照；
  AutoPoi `exportBigExcel` SXSSF 流式写；`.part` 临时文件成功后原子改名。
- 行数守卫 1048573（数据行，扣除 2 标题 + 1 表头），超限任务 FAILED 并给出缩小条件文案。
- 终态（含 FAILED）统一写 `expire_time = finish + 7d`；清理 Job（03:00）按 `expire_time` 先删文件再删记录，
  分批 200；启动恢复把孤儿 PENDING/RUNNING 置 FAILED（文案「服务重启，任务中断，请重试」）。
- 归属判定只用登录人（`WmsUtils.currentUsername()`），后台线程不碰 Shiro。

### 1.3 前端（`src/views/wms/inventoryLedger/`）

- 查询条件：物料关键字 / 批次 / 库位 / 仓库下拉（**含停用仓**，文案带「（停用）」）/ 只看有库存（默认勾选）。
- 明细表 15 列，仓库状态用 tag（启用绿 / 停用灰）；空态区分「未查询」与「未找到匹配的库存记录」。
- 我的导出任务：状态 tag、5 秒轮询（全部终态自动停、`onUnmounted` 清定时器）、过期置灰、删除带确认。

## 3. 实现期发现（均已修复并有回归测试）

1. **AutoPoi 十万行滚动分页**（commit `407c5942`）：`ExportParams.maxNum` 默认取
   `USE_SXSSF_LIMIT=100000`，超限滚动到**没有表头**的 Sheet1/2/3 继续写。数据不丢（30 万行实测 4 个 sheet 分毫不差），
   但财务没法用，且永远轮不到自定义的超限文案。修复：`buildExportParams` 显式 `setMaxNum(1048576)` 禁滚动；
   数据行守卫改为 1048573（扣除 2 标题 + 1 表头，不撞 xlsx 物理上限）。
2. **前端任务表缺「操作」列**（commit `a0d604bd`）：`taskColumns` 漏定义 action 列，下载/重试/删除按钮无处渲染；
   同时 `handleExportXlsx` 会自补 `.xlsx`，传带后缀文件名会变成 `.xlsx.xlsx`。两处已修，chromium 实测通过。

## 4. 环境事件（与本项目代码无关，但影响过验证过程）

- 验证期间发现 8081 上残留一个**旧代码的孤儿 JVM**（上个会话遗留），它把 QRTZ 里 7 个同步类任务的 trigger
  打成 ERROR 状态（旧 classpath 加载不到新任务类）。已：杀掉孤儿、删除 7 条 ERROR trigger、正常重启后注册器全部重建。
  这正是 2026-10-27「9 个任务注册器静默失效」收口时防的坑——`WmsJobRegistrarSupport` 的残留重建逻辑这次实际生效。
- 归属隔离测试需要第二个有导出权限的账号：给 zhangsan 临时授了 admin 角色并用平台接口把其密码重置为 `123456`
  （原密码不明），**测试后已回收临时角色**；zhangsan 密码现为 `123456`，如需改回请自行调整。
