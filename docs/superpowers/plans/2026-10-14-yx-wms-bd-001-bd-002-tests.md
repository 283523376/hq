> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 `jeecg-boot-module-wms` 补全 BD-001（物料与分类）的全部自动化测试，并补齐 BD-002（供应商与订单）缺失的服务层用例，以及**两个模块此前完全为零的 Controller 层用例**与**物料批量导入/导出用例**。

**Architecture:** 沿用本模块已确立的测试形态——**纯 Mockito 单测，不启 Spring 上下文、不连库**（现有 6 个测试类 41 用例即此形态，全部在 8 秒内跑完）。控制器测试采用「直接 `new Controller` + 反射注入继承自 `JeecgController` 的 `protected service` 字段 + 断言 `Result<T>`」的方式，可完整覆盖 `try/catch → Result.error` 的消息映射，且不需要 Shiro 过滤器链或 `@WebMvcTest` 切片。导入/导出用真实 POI 生成的 xlsx + `MockMultipartHttpServletRequest` 驱动。

**Tech Stack:** JUnit 5（`org.junit.jupiter.api.Assertions`，**非** AssertJ）/ Mockito 5.23（`mock()` + `spy()` + `doReturn`）/ Apache POI 5.5.1（构造 xlsx）/ spring-test 7.0.8（`MockMultipartHttpServletRequest`、`MockHttpServletRequest`）/ MyBatis-Plus 3.5.16 / Shiro（`DefaultSecurityManager` 空绑定）。全部依赖已由根 pom 的 `spring-boot-starter-test` 与模块现有依赖传递提供，**无需改任何 pom**。

**Spec:** 本计划无独立设计文档——按已确认的决策「**以现有实现代码的行为为基准**」编写。行为权威来源：

## Global Constraints

以下为项目级硬约束，**每个任务都隐含包含本节**。多数来自 BD-002 计划实测所得，勿凭经验替换。

**工具链（已实测）**

- **Maven 不在 PATH**。一律写成 `bash /d/tools/m.sh <args>`（脚本设好 `JAVA_HOME` 后转调 `D:/tools/apache-maven-3.9.9/bin/mvn.cmd`）。裸跑 `mvn` 会 `command not found`。
- 模块目录：`jeecg-boot/jeecg-boot-module/jeecg-boot-module-wms`。
- **本计划的回归命令**（已实测 41 用例全绿，8 秒内）：

  ```bash
  cd jeecg-boot
  bash /d/tools/m.sh -P dev -pl jeecg-boot-module/jeecg-boot-module-wms -am test \
    -DskipTests=false -Dtest='Wms*Test,Http*Test' -Dsurefire.failIfNoSpecifiedTests=false
  ```

  说明：`-P dev` 在 `-pl <module>` 单模块测试下并非必需（实测不带也通过），但保留以与 BD-002 计划一致，并避免将来改为根级 `clean package` 时踩到「`dev`/`SpringCloud` 同为 activeByDefault」的坑。`-DskipTests=false` 必需（测试默认被跳过）。
- 单跑一个测试类：把 `-Dtest='Wms*Test,Http*Test'` 换成 `-Dtest=<ClassName>`。
- **无 `mysql` CLI**。本计划**不需要**数据库——全部测试不连库。

**测试形态（本仓库铁律，勿改）**

- **不启 Spring 上下文**。不引入 `@SpringBootTest` / `@WebMvcTest` / `@MockBean` / `@SpyBean` / `@Sql` / H2 / Testcontainers。理由：JeecgBoot 全上下文依赖 MySQL + Redis + Shiro + Quartz，且现有 6 个测试类全部是纯 Mockito；引入全上下文会让模块测试从 8 秒变成数十秒且大概率起不来。
- 断言一律 `org.junit.jupiter.api.Assertions.*` 静态导入；**不使用 AssertJ**（虽在 classpath 上），**不使用 `@DisplayName`**——与既有测试类保持一致。
- 被测服务：`spy(new XxxServiceImpl())`，对继承自 `ServiceImpl` 的方法用 `doReturn(...).when(service).xxx(...)` 打桩。
- 被测控制器：`new XxxController()` + `WmsTestSupport.inject(controller, "service", mockService)`。
- 测试类为**包级私有** `class XxxTest`，与被测类同包。
- 类头保留中文 Javadoc：`@Description: ...（不启 Spring 上下文、不连库）` / `@Author: 永鑫WMS` / `@Date: 2026-10-14`。
- 每个测试方法上方一行中文 Javadoc 说明**它守住的不变量**（既有测试的做法），不写「测试 XX」这类同义反复。
- 测试方法命名：`行为_条件` 或 `行为_shouldXxx`，英文小驼峰（沿用既有风格）。

**Mockito 匹配器（已实测的坑，照抄）**

- **`any()` 遇重载歧义必须显式给类型**。`IService` 同时有 `list(Wrapper)` 与 `list(IPage)`，`list(any())` **编译不过**；实测必须 `any(Wrapper.class)`。同理 `removeByIds(any(Collection.class))`、`count(any(Wrapper.class))`、`page(any(Page.class), any(Wrapper.class))`。
- 下列形式**已实测编译通过**，可直接使用：`checkCodeExists(any(), any())`、`save(any())`、`updateById(any())`、`removeById("1")`、`hasMaterial("C1")`、`getOne(any(Wrapper.class), eq(false))`、`selectCount(any(Wrapper.class))`、`selectBatchIds(any())`、`selectOne(any(Wrapper.class))`。
- **spy 打桩会遮蔽真实实现**：在 spy 上 `doReturn(false).when(service).hasMaterial(id)` 后，`hasMaterial` 的真实实现（走 mapper）就不再执行。因此「测 `removeCategory` 的守卫分支（打桩 `hasMaterial`）」与「测 `hasMaterial` 本身（注入 mock mapper）」**必须是两个不同的测试方法**，不能合并。实测中曾把二者写在一起，导致断言自相矛盾。

**被测代码的关键事实（写断言前务必对齐）**

- `org.jeecg.common.util.oConvertUtils.isEmpty(Object)` **不做 trim**：只把 `null`、`""`、`"null"` 视为空。`"   "`（纯空白）**不是**空串。多处断言依赖此语义。
- `SelectTreeModel` 的布尔字段是 `isLeaf`（Lombok 生成 `isLeaf()` / `setLeaf(...)`）——**没有 `getLeaf()`**，断言必须写 `isLeaf()`。
- `WmsUtils.currentUsername()` 在无登录上下文时返回 **null**（内部 try/catch），故单测无 Shiro 上下文时 `createBy` / `updateBy` / `auditBy` / `dispatchBy` 恒为 null。**不要**断言这些字段的取值。
- 业务异常一律是 `RuntimeException`（**本仓库没有 `BusinessException`**），断言用 `assertThrows(RuntimeException.class, ...)` + `assertEquals(消息, ex.getMessage())`。
- `Result` 语义：`Result.OK(data)` → code 200、success true、message ""；`Result.OK(msg)` → code 200、message=msg、**result 也被置为 msg**；`Result.OK(msg, data)` → code 200、message=msg、result=data；`Result.error(msg)` → **code 500**、success false、message=msg。
- 导入返回值：全部成功时 `code=200`、message `共N行数据全部导入成功！`；有错误行时 **`code=201`**、message `文件导入成功，但有错误。`、result 为含 `totalCount/errorCount/successCount/fileUrl/fileName` 的 JSON 对象。
- **筛选值必须设在「实体入参」上，不能只塞 request 参数**（已实测 + 读源码核实）。`QueryGenerator.installMplus` 只从**实体字段值**（`PropertyUtils.getSimpleProperty(searchObj, name)`）构造条件；`request.getParameterMap()` **仅**用于 `_begin`/`_end` 区间查询与排序列（`column`/`order`）。真实链路是「前端把筛选值作为查询参数 → Spring 绑定进控制器的实体入参 → QueryGenerator 读实体值」。测试里写 `new WmsOrder()` + `request.addParameter("orderType", ...)` 会构造出**零条件**，`getSqlSegment()` 只剩 `ORDER BY create_time DESC`。
- **要断言 `QueryWrapper` 的条件，必须先调 `getSqlSegment()`**（已实测）。MyBatis-Plus 的 `AbstractWrapper` 条件参数是**惰性填充**的：不渲染片段时 `getParamNameValuePairs()` 恒为空 `{}`。后果分两个方向——
  - 断言「必须包含」会**误报失败**（参数集合本来就空）；
  - 断言「必须不包含」会**退化成永真断言**（空集合上 `containsValue` 恒 false，`assertFalse` 永远通过），比没有断言更糟。
  正确写法：`String sqlSegment = wrapper.getSqlSegment();` 然后断言**列名**，例如
  `assertTrue(sqlSegment.contains("supplier_code"))` / `assertFalse(sqlSegment.contains("category_name"))`；参数值断言放在其后。实测渲染结果形如 `(supplier_code = #{ew.paramNameValuePairs.MPGENVAL1})`。

**验证纪律**

- 每个 Task 的收尾步骤是**跑该 Task 的测试类并贴出实际输出**，然后跑一次全模块回归。

## Review Focus

以下是本测试套件**最容易被漏掉、一旦漏掉就会让绿灯失去意义**的五类输入/失败模式。每条都已在「归属任务」写了对应测试，实现时不要删。

1. **导入 Excel 中「分类编码不存在」的行**：必须报出**物理行号**（第 4 行起，与模板的两行标题 + 一行表头对齐），且**不影响同文件其它行入库**（逐行收集错误、刻意无事务）。报错行号算错（如报成「第 2 行」或列表下标）会让用户照着提示改错行。→ 归属 Task 5。
2. **导入 Excel 中两种「重复」必须可区分**：文件内重复 →「物料编码 X 在文件中重复」；库内已存在 →「编码已存在，请重新输入」。混为一谈会让用户无法判断该改文件还是改库。→ 归属 Task 5。
3. **纯空白编码（`"   "`）**：`oConvertUtils.isEmpty` **不 trim**，而 `WmsMaterialServiceImpl` / `WmsMaterialCategoryServiceImpl` **既不 trim 也不判空**（对比：供应商与订单两条路径都做了 trim + 判空）。结果是空白编码能被入库，且 `"   "` 与 `""` 在唯一索引下是不同值。这是 BD-002 Review Focus #2 曾专门修过的同类缺陷，**在 BD-001 因零测试而从未被发现**。→ 归属 Task 2、Task 3，并上报缺口 G-TRIM。
4. **空 Excel（仅表头）**：当前实现走 `imporReturnRes(0, 0, [])`，返回「共0行数据全部导入成功！」而非蓝图期望的「文件内容为空」。测试必须**固化这一现状**（而非照规格断言），否则要么永远红、要么悄悄放过。→ 归属 Task 5。
5. **分类/供应商已被删除后，历史列表仍须能渲染**：回填必须对「查不到的 id」静默留空，不得抛异常让整个列表 500。→ 归属 Task 3 `fillCategoryInfo_shouldTolerateMissingCategory`；供应商侧已有既有测试覆盖。

package org.jeecg.modules.wms.support;

import org.apache.poi.ss.usermodel.Row;
import org.apache.poi.ss.usermodel.Sheet;
import org.apache.poi.xssf.usermodel.XSSFWorkbook;
import org.apache.shiro.SecurityUtils;
import org.apache.shiro.mgt.DefaultSecurityManager;

import java.io.ByteArrayOutputStream;
import java.lang.reflect.Field;
import java.util.List;

/**
 * @Description: WMS 测试支撑工具（反射注入 / Shiro 空上下文 / 导入模板 xlsx 构造）
 * @Author: 永鑫WMS
 * @Date: 2026-10-14
 */
public final class WmsTestSupport {

    private WmsTestSupport() {
    }

    /**
     * 沿继承链查找并注入字段。
     *
     * <p><b>为什么需要反射</b>：{@code JeecgController.service} 是声明在**另一个包**
     * （{@code org.jeecg.common.system.base.controller}）的 protected 字段——测试类即使与该
     * Controller 同包也无权赋值；{@code ServiceImpl.baseMapper} 同理。反射是唯一**不动生产代码**
     * 的注入方式（备选方案是给每个 Controller 加 {@code setXxxForTest} 专用 setter，但那要为
     * 4 个已上线控制器增加测试专用 API）。
     */
    public static void inject(Object target, String fieldName, Object value) {
        Class<?> clazz = target.getClass();
        while (clazz != null) {
            try {
                Field field = clazz.getDeclaredField(fieldName);
                field.setAccessible(true);
                field.set(target, value);
                return;
            } catch (NoSuchFieldException e) {
                clazz = clazz.getSuperclass();
            } catch (IllegalAccessException e) {
                throw new IllegalStateException("注入字段失败：" + fieldName, e);
            }
        }
        throw new IllegalStateException(
                "未在继承链上找到字段：" + target.getClass().getName() + "#" + fieldName);
    }

    /**
     * 绑定一个空的 Shiro SecurityManager。
     *
     * <p>{@code WmsMaterialController.exportXls} 直接调用 {@code SecurityUtils.getSubject()} 且**未包 try/catch**，
     * 无绑定会抛 {@code UnavailableSecurityManagerException}；绑定后 {@code getPrincipal()} 返回 null，
     * 恰好覆盖控制器里 {@code user == null ? "" : user.getRealname()} 的分支。
     */
    public static void bindShiro() {
        SecurityUtils.setSecurityManager(new DefaultSecurityManager());
    }

    /** 解绑，避免污染同一 JVM 内的其它测试。 */
    public static void unbindShiro() {
        SecurityUtils.setSecurityManager(null);
    }

    /**
     * 构造与平台导入模板格式一致的 xlsx：第 1 行标题、第 2 行填写说明、第 3 行表头，数据自物理第 4 行起。
     *
     * <p>列顺序与 {@code WmsConstants.IMPORT_ROW_OFFSET}（=4）的约定一致：
     * 物料编码、物料名称、分类编码、规格。
     *
     * @param dataRows 数据行，每行按上述 4 列顺序；传 {@code null} 或空列表即「仅表头」的空文件
     */
    public static byte[] materialXlsx(List<String[]> dataRows) {
        try (XSSFWorkbook workbook = new XSSFWorkbook();
             ByteArrayOutputStream out = new ByteArrayOutputStream()) {
            Sheet sheet = workbook.createSheet("物料");
            sheet.createRow(0).createCell(0).setCellValue("物料列表");
            sheet.createRow(1).createCell(0).setCellValue("填写说明：物料编码、物料名称、分类编码为必填");
            Row head = sheet.createRow(2);
            head.createCell(0).setCellValue("物料编码");
            head.createCell(1).setCellValue("物料名称");
            head.createCell(2).setCellValue("分类编码");
            head.createCell(3).setCellValue("规格");
            if (dataRows != null) {
                for (int i = 0; i < dataRows.size(); i++) {
                    Row row = sheet.createRow(3 + i);
                    String[] values = dataRows.get(i);
                    for (int column = 0; column < values.length; column++) {
                        row.createCell(column).setCellValue(values[column] == null ? "" : values[column]);
                    }
                }
            }
            workbook.write(out);
            return out.toByteArray();
        } catch (Exception e) {
            throw new IllegalStateException("构造测试 xlsx 失败", e);
        }
    }
}

    }

        assertEquals(service, child.service);

                () -> WmsTestSupport.inject(new Child(), "noSuchField", new Object()));

                new String[]{"M002", "螺母", "CAT-BAN", "M8"}));

        params.setHeadRows(1);

        } finally {
            WmsTestSupport.unbindShiro();
