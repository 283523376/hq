# 金蝶发货通知单（SAL_DELIVERYNOTICE）只读探测报告

- 日期：2026-10-28
- 性质：**只读探测**，未创建/修改任何金蝶单据
- 目的：为「销售出库由金蝶发货通知生成 WMS 待办」提供事实依据，据此出实施方案
- 环境：219.139.47.222:2021 测试账套，组织 101（宜昌永鑫）/ 100（江西兆鑫）

## 1. 表单与字段（QueryBusinessInfo 实测）

| 项 | 结果 |
|---|---|
| 表单名 | 发货通知单 |
| 单据类型 | `FHTZD01_SYS` 标准发货通知单（另有受托/寄售/VMI/分销购销/分销调拨 5 种） |

`FDeliveryDate`（要货日期）、`FSumOutQty`（累计出库数量）、`FIsFree`（赠品）

## 3. 探测发现的三个阻塞点（必须先解决）

### 3.1 出货仓库与 WMS 库区没有映射

金蝶出货仓库为 `S.05 / S.09 / K.045 / CK007 / Y.41` 等，WMS 库区只有
`LB 半成品仓 / XB01 / FPC01 废品仓 / MJ 产成品仓 / CJ 初级产成品仓 / TC 涂层产成品仓`。
**没有对应关系，直接生成待办会指向 WMS 不存在的库区。**

### 3.2 物料可能不在 WMS 主数据

抽查 4 个组织 101 的未出库物料（`Y.S.002.0085`、`X.P.007.0073`、`W.A.008.0047`、
`XA.00.06010101.04601703.B007`），WMS `wms_material` 命中 **0/4**——
物料同步只覆盖 `master-data.org-id`（101）下的 500 条，而这些物料可能归属其它组织或为后建。

### 3.3 源销售订单不在 WMS 快照

`FHTZD009023` 的源单 `XSDD003944` 不在 `wms_sales_order`（当前仅 7 条快照，均为更早期单据）。
**不能假设「发货通知的源销售订单一定已同步」**，否则待办生成会缺上下文。

## 4. 建议方案（待确认，尚未实现）

```
扫描 SAL_DELIVERYNOTICE：FDocumentStatus ∈ {B, C} 且 FRemainOutQty > 0
  └─> 仓库映射：金蝶出货仓库 → WMS 库区（新增映射配置/表），未命中则跳过并记原因
        └─> 物料：WmsMaterialCodeResolver 反查；未命中跳过（原因：物料未同步）
              └─> 生成 WMS 销售出库单（待分配），明细数量 = FRemainOutQty，批号 = FLot
                    ├─ 幂等：明细 source_entry_id 记 `发货通知单号#分录ID`，已生成的不重复
                    └─ 客户/销售组织取自发货通知单头（客户编码经金蝶 lookup 校验）
```

- 触发：销售订单同步任务后追加一轮 + 出库页手工按钮（与领料待办同构）
- 不依赖源销售订单快照：待办单只在备注记源单号，需要详情时按需查金蝶

## 5. 需要业务确认的三件事

1. **仓映射口径**：WMS 的「MJ 成品敏捷仓」对应金蝶哪个（哪些）出货仓库？
   其余金蝶仓库是否根本不由 WMS 管理（即直接跳过）？
2. **准入状态**：发货通知单在 `B`（已提交）就生成待办，还是必须等 `C`（已审核）？
   （测试账套里 B 态未出库单不少，若只认 C 会漏掉一半候选）
3. **分批发货**：`FRemainOutQty` 会随出库递减，是否允许对同一行多次生成待办（分批出库）？
   建议允许，靠「在途量」扣减，与领料待办口径一致。
