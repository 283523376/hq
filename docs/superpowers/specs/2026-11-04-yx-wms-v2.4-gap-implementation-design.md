# 蓝图 V2.4 差距落地 设计方案

- 日期：2026-11-04
- 依据：`D:\资料\软件蓝图\永鑫WMS软件蓝图V2.4（评审中）-20261103.docx`
- 现状基线：SB-001 已交付；代码基线 1290 单测全绿
- 目标：把 V2.4 相对当前实现的差距落成可实施的设计

---

## 1. 已定口径（2026-11-03/04 用户确认）

1. 受托入库走金蝶 **受托加工材料入库单**；退货走 **ERP 供应链→采购管理**的采购退货单。
2. **大改小 = 原材料加工成成品，走生产入库**；ERP 生产订单先行，WMS 只同步，不自建生产订单。
3. 段差棒按 ERP 口径，所有物料信息从 ERP 同步。
4. 受托方复用供应商档案。
5. 员工身份 = **当前登录账号**（不做下拉、不做读卡器）。
6. 受托材料所有权不属于企业，**单独记「受托库存」**，并**按受托方隔离**（复用供应商档案）。
7. 受托不良入废品仓**不转自有**，仍记受托方名下。
8. 大改小的原材料**不进 WMS 库存**（含受托来源），WMS 只登记改制单投入数量。

## 2. 范围

| 纳入 | 不纳入 |
| --- | --- |
| RK-001 外购/受托原材料入库（含大改小、段差棒） | 采购检验流程（仍停用） |
| RK-005 不良品两类来源（生产 / 受托） | XT-001 退货（明确不做） |
| CK-001 领料动作细化 | 工牌读卡器、员工档案同步 |
| 受托库存模型 | 原材料线边柜/智能柜 |
| 菜单与权限补齐 | 历史数据迁移（不动存量） |

## 3. 方案

### 3.1 受托库存模型

- `wms_inventory` 增加 `ownership_type`（`OWNED` 自有 / `CONSIGNED` 受托，默认 `OWNED`）与 `consignor_id`（受托方，自有为空）。
- 唯一键 `uk_wms_inv_mat_loc_batch_container` 改为六列（加 `ownership_type`、`consignor_id`），避免自有与受托、不同受托方之间被合并。
- 库存查询、台账、导出增加「库存类型」筛选与列；**默认只显示自有库存**，受托需显式筛选。
- 业务约束：
  - 受托库存不得用于自有生产领料、销售出库；
  - 受托库存只能用于退货或报废处置（大改小原材料不入库，不存在受托领用出库）；
  - 出库分配（`selectAvailable`）默认只取 `OWNED`，受托场景单独走受托出库。
- **对账口径（本方案裁决）**：SB-001 对账域**暂只含自有库存**；受托库存不参与金蝶即时库存对账，后续按需扩展。

### 3.2 RK-001 外购/受托原材料入库

**到货登记**
- 数据来源：ERP 采购订单 / 受托订单（新增 Reader，`PUR_*` 类，formId 待控制台确认）。
- 新增入库单来源类型：`source_type = PURCHASE | CONSIGNED`。
- 处理方式二选一：`大改小` / `段差棒直入`。

**段差棒直入**
- 到货 → 分配半成品立库货位 → 下发堆垛机 → 回执 → 按自有库存入账 → 回写金蝶 **采购入库单**。

**大改小**
- 前提：ERP 生产订单（PRD_MO）已审核并同步至 WMS（BD-002 通道）。
- WMS 创建**改制单**，记录投入原材料（物料/批次/数量）与产出半成品（物料/批次/数量），关联生产订单号。
- 原材料**不入 WMS 库存**（直送车间），WMS 只登记投入数量；产出半成品走生产入库（复用 RK-002 通道）。
- 执行：改制单完成 → 生成生产入库单 → 分配立库货位 → 设备入库 → 库存入账。
- ERP 回写：产出走 **PRD_INSTOCK**（复用现有 Writer）；投入由 ERP 生产订单领料记账，WMS 不重复写。
- 原材料（含受托来源）**不入 WMS 库存**：到货只做登记，物料直送车间；产出半成品为自有库存入立库。受托加工领用台账由 ERP 生产订单领料负责，WMS 不重复记账。

**受托入库**
- 到货 `source_type=CONSIGNED` → 入受托库存（`ownership_type=CONSIGNED`）→ 回写金蝶 **受托加工材料入库单**。

### 3.3 RK-005 不良品两大类来源

- 新增 `wms_defect_record`：来源类型（生产/受托）、来源单号、物料、批次、数量、原因、处置方式（入废品仓/退货）、状态、退货单号。
- **生产不良**：由生产入库单不良数量生成；入废品仓（自有）。
- **受托原材料不良**：由受托到货/检验登记生成；扣减受托库存；处置二选一：
  - 入废品仓：**不转自有**，按受托方单独记废品仓库存行（`ownership_type=CONSIGNED`），报废/退货仍按受托处置；
  - 退货：生成 **采购退货单**（ERP 采购管理）并通知受托方。
- 复用 XT-001 的报废出口做最终处置。

### 3.4 CK-001 生产领料动作

- **员工身份**：取当前登录账号（`LoginUser`），写入领料记录 `picker_id/picker_name`；不做下拉、不做读卡器。
- **设备**：领料时选择设备，出库单记录 `device_id`。
- **数量**：支持部分领料，`pickQty`（本次数量）不得超过工单需求。
- **取消与通知**：物料不符或库存不足时，取消出库单并发送站内消息给计划员/工单创建人。
- **领料记录**：出库单 + 明细 + 领取人 + 设备 + 工单号，作为蓝图所指「领料记录」。

### 3.5 菜单与权限

- 恢复「供应商」入口（受托方复用）。
- 入库管理新增「外购/受托原材料入库」。
- 不良品处置新增「不良品入库登记」入口（或在入库页内）。
- 新增权限码：`wms:inbound:consigned`、`wms:conversion:*`、`wms:defect:inbound`、`wms:outbound:pick:cancel`。

## 4. 数据模型（Flyway `V3.9.5_47` 起）

| 表 | 字段 |
| --- | --- |
| `wms_inventory` | + `ownership_type varchar(16) NOT NULL DEFAULT 'OWNED'`、+ `consignor_id varchar(36) NOT NULL DEFAULT ''`（空串=自有；不可为空，否则 MySQL 唯一索引对 NULL 不去重会让六列键失效）；重建唯一键为 `(material_id, location_id, batch_no, container_code, ownership_type, consignor_id)` |
| `wms_inbound_order` | + `source_type varchar(16)`、+ `conversion_order_id varchar(36)` |
| `wms_inbound_detail` | + `source_material_code varchar(64)` |
| `wms_conversion_order` | 新增：单号、生产订单号、投入物料/批次/数量、产出物料/批次/计划数量、状态、操作人、ERP 单号 |
| `wms_conversion_detail` | 新增：投入/产出明细行（方向、物料、批次、数量） |
| `wms_defect_record` | 新增：来源类型、来源单号、物料/批次/数量、原因、处置方式、退货单号、状态 |
| `wms_outbound_order` | + `picker_id`、`picker_name`、`device_id`、`cancel_reason` |

> 存量数据：`ownership_type` 默认 OWNED；唯一键重建前先校验无重复（迁移脚本里做一次 `SELECT` 守卫，失败即中止）。

## 7. 风险

| 风险 | 应对 |
| --- | --- |
| 受托加工入库单/采购退货单 formId 未确认 | 先用控制台验证，再写 Writer |
| 受托不良入废品仓 | 已定：不转自有，按受托方分行记账 |
| 唯一键重建影响存量数据 | 迁移前做重复校验，失败即中止 |
| 大改小原材料不入 WMS 库存 | 与「库内可追溯」要求可能冲突，需确认是否要记原材料流水 |
| 受托库存不纳入 SB-001 对账 | 本期明确排除，后续扩展 |

## 8. 验收

1. 单测：受托库存隔离、唯一键、改制单流转、不良两类来源、领料部分数量与取消通知。
2. 真账套：段差棒入库、受托入库、大改小（生产订单→领料→生产入库）、受托不良退货各跑一单。
3. Flyway `success=1`，启动日志无失败。
4. 前端页面与权限码齐备，`pnpm build` 通过。
5. 库存查询默认不显示受托，筛选后可见。
