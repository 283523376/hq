# 设计：wms-logicflow-designer 泳道流程图编辑器

日期：2026-10-12
状态：待用户评审

## 1. 目标与验收标准

### 目标

让 `wms-logicflow-designer` 在图形界面里**拖拉拽地创建、修改泳道流程图**，参考基准是一张「WMS 收货入库流程」泳道图（6 个角色列 + 左侧步骤号列 + 21 个带编号的节点 + 实线主流程与红色虚线异常流程）。同时保留现有的思维导图模式，并交付一份使用说明。

### 验收标准

1. 打开应用切到「流程图」模式，看到与参考图一致的**可编辑**图：6 条泳道表头与配色、步骤号列、21 个节点（A01–A21）的所在列与所在步骤、节点配色、连线类型（实线 / 红虚线）与连线文字标签。
2. 可以拖拽新增节点、跨泳道移动节点、双击改文字、双击改连线标签、从锚点拉出连线、删除元素；撤销/重做、多选、对齐吸附由 LogicFlow 配置项提供（不额外写 UI）。
3. 增删泳道、改泳道名之后，已有节点**自动重排且不错位**。
4. 刷新浏览器不丢内容；导出 JSON 后再导入能还原同一张图；导出 PNG 可用（复用导图版已有的 Snapshot 深路径写法）。
5. `pnpm build`（类型检查）与 `pnpm test`（Vitest）通过。

### 关于范围的取舍（2026-10-12 追加）

用户要求「砍掉不必要的功能，以最少代码实现」，故本设计已按最小集收敛。**被砍掉的能力**（如需再议，改这一节即可）：

- **右栏属性面板**——改由「双击就地编辑」+ 工具栏少量按钮替代。
- **连线手动调走线**（`waypoints`）——只保留自动肘形路由。
- **多文档管理**（文档索引 / 新建 / 命名 / 切换 / 删除）——只保存一份文档。
- **复制粘贴剪贴板**——多选 + Delete 已覆盖多数场景。
- **泳道调宽 / 排序 / 配色编辑的 UI**——这三项改 JSON 即可；保留添加 / 删除 / 双击改名。
- **工具栏的多数按钮**——只留：添加泳道、步骤 +/−、导出 JSON、导入 JSON、导出 PNG、重置为示例。
- 实施分期由四期收敛为**两阶段**（A 渲染、B 编辑）。

**保留但「免费」的能力**（纯配置项，不写 UI）：撤销/重做（`history`）、多选（`multipleSelectKey`）、对齐吸附（`snapline`）、Delete 删除、锚点拖拽建边。

## 2. 非目标（Out of scope）

- 不做后端、账号、多人协作、权限、云端同步。
- 不做判断菱形、起止框等更多节点形状（模型留 `kind` 字段，本期只有一种）。
- 不做自动布局算法——位置由网格决定，不需要布局器。
- 不做思维导图的编辑，导图模式维持现状（只读渲染）。
- 不做跨文档复制粘贴、版本历史、评论/批注。

## 3. 已确认的决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 应用结构 | 双模式并存，顶部切换 | 现有导图已调好（自动布局 + 括号连线），编辑能力做成纯增量 |
| 持久化 | localStorage（**单份文档**）+ JSON 导入导出 | 纯前端、可离线。多文档管理按最小化砍掉 |
| 初始内容 | 内置参考图为示例文档 | 打开即可验证效果，「修改」是真实场景；另留「重置为示例」 |
| 功能范围 | **最小集**：拖拽建/移节点、双击改文字与连线标签、拉线、删除、增删泳道、JSON 存取 | 用户先选四项全要，后要求「砍掉不必要的功能，以最少代码实现」，故收敛（被砍清单见 §1 末） |
| 布局模型 | **网格锚定**：节点存 `{laneId, step}`，坐标推导 | 参考图本质是网格图；增删泳道自动重排；JSON 人可读可 diff |
| 节点配色 | 取自所属泳道，不逐节点存色 | 参考图 21 个节点无一例外，配色是规则而非巧合 |
| 落点冲突 | 自动顺延到同列最近空格子 | 不打断拖拽操作 |
| 测试 | 新增 Vitest（devDependency） | 「增删泳道自动重排」正确性靠手点难覆盖；几何与校验是纯函数 |
| 推进方式 | **两阶段**：A 渲染、B 编辑；A 单独验收 | A 先渲染出参考图，先验掉转录与几何（验收基线），再盖编辑器 |

## 4. 数据模型

唯一事实源是一份文档，**不存坐标**。放在 `src/editor/types.ts`。

```ts
export type LaneColor = 'blue' | 'orange' | 'green' | 'purple' | 'red'

/** 网格参数：决定列宽/行高如何变成像素 */
export interface GridConfig {
  headerHeight: number       // 泳道表头行高
  stepColumnWidth: number    // 左侧「步骤」号列宽度
  rowHeight: number          // 每个步骤行的高度
  lanePadX: number           // 节点相对泳道左右的内边距
  lanePadY: number           // 节点相对行带上下留有呼吸空间
}

export interface Lane {
  id: string                 // 'lane-1' 等，稳定即可
  name: string               // 「收货员」
  color: LaneColor           // 决定表头与该列节点配色
  width: number              // 列宽；节点宽 = width - 2 * lanePadX
}

export interface FlowNode {
  id: string                 // A01 风格，可手改
  text: string               // 换行由宽度自动计算；若文本里含 \n 则按硬换行优先处理
  laneId: string
  step: number               // 1-based 行号
  kind: 'process'            // 预留扩展，本期只此一种
}

export interface FlowEdge {
  id: string
  source: string             // node id
  target: string
  label?: string             // 连线上的文字标签，自由文本，编辑器不限定取值
  kind: 'main' | 'exception' // 决定线型与颜色
}

/** 一张泳道流程图文档 */
export interface FlowDoc {
  schemaVersion: 1
  id: string
  name: string
  updatedAt: string          // ISO 时间
  grid: GridConfig
  lanes: Lane[]
  stepCount: number
  nodes: FlowNode[]
  edges: FlowEdge[]
}

// 手动调走线（waypoints）已按最小化砍掉：连线只走自动肘形路由。
```

不做逐节点颜色覆盖：节点配色完全由 `lane.color` 推导（这是第 3 节已确认的决策）。

**模型对业务内容完全无知**：它不认识任何具体流程术语，`text` 与 `label` 都是自由文本，编辑器不预设取值、不做校验。所有 WMS 专有的词（`A01`、`合格改刀料`、`不合格品`…）只作为**数据**出现在第 9 节的示例图里，不是模型的一部分——`label` 也不限于这几个值。

## 5. 几何推导

纯函数，放 `src/editor/geometry.ts`，不碰 DOM、不碰 LogicFlow，因此可直接单测。

```
laneLeft(0) = grid.stepColumnWidth
laneLeft(n+1) = laneLeft(n) + lanes[n].width

nodeRect(node):
  lane   = lanes.find(l => l.id === node.laneId)
  width  = lane.width - 2 * grid.lanePadX
  x      = 列中心 = laneLeft(lane) + lane.width / 2
  y      = 行带中线 = grid.headerHeight + (node.step - 1) * grid.rowHeight + grid.rowHeight / 2
  height = wrappedTextHeight(node.text, 内容宽) + 2 * 文本内边距
```

`wrappedTextHeight` 在 `src/editor/text.ts`：沿用 `layout/mindmap.ts` 里 `measureText` 的估宽思路（CJK 计 1em、Latin 计 0.55em），逐字累加，超宽即换行，行数 × 行高 + 内边距得到高度。**这是参考图里 A03（4 行文字）比 A07（1 行）高得多的原因**——高度由文字决定，不是手调的。

三条规则合起来解释了参考图为什么整齐：同一列节点宽度天然相等（列宽决定），同一行节点纵向对齐（行带决定），高度随文字自适应。

**刻意的少量重复**：不把 `measureText` 抽成共享模块，因为导图版只做单行估宽、编辑器版要做换行，职责不同；而用户已明确「导图部分不动」。(`layout/mindmap.ts` 一行不改。)

文档总尺寸（供 `frameGraph` 用）：
```
width  = stepColumnWidth + Σ lane.width
height = headerHeight + stepCount * rowHeight
```

### 5.1 结构变更的守恒规则

不变式：`1 ≤ node.step ≤ stepCount`，且同一格里的节点**横向不重叠**。所有编辑操作必须维持它，`validateDoc()` 在加载/导入时校验它。

> **2026-10-12 实施期修订**：原不变式是「每个格子最多一个节点」。转录参考图时发现 **A13 与 A14 在原图里就是同一格并排的两个节点**（同属「待切头/柄料」第 6 步），该不变式表达不了它。故给 `FlowNode` 增加可选的 `width`（收窄）与 `offsetX`（左右错开），校验由「禁重复格」改为「**禁横向重叠**」——同格两个不重叠的节点是合法表达，重叠才是画错。用户侧的编辑操作（`ops.ts`）仍然只往空格子放，所以手工编辑不会产生同格并排。

- **减少步骤数**：`stepCount` 调到 N 后，`step > N` 的节点自动上移到第 N 格；该格已占则继续向上顺延，并列出被移动的节点。**绝不静默删除节点。** 若格子确实不够（`泳道数 × N < 节点总数`），则**拒绝这次操作并提示**——拒绝是可恢复的，把节点堆成重复格留下坏数据不是。
- **删除泳道**：若该泳道内仍有节点，**拒绝删除**并提示先移走或删除这些节点（不连带删除节点）。
- **重置为示例**：先确认（会丢掉尚未导出的改动）。
- **添加步骤 / 添加泳道**：只追加空行带或空列，不改动任何已有节点。

## 6. 渲染层

### 节点（`src/editor/nodes/FlowNode.ts`）

自定义 LogicFlow 节点 `flow-node`，一个圆角矩形里画两段样式不同的内容：**左上角编号徽章**（A01，小号、浅底色）+ **居中的多行正文**。内置 `rect` 做不到——它的 `text` 是单段统一样式。

视图用核心导出的 `h()` **显式调用**（`@logicflow/core` 的 index 已 `export { h }`），**不写 JSX**：LogicFlow 的视图层是 preact，项目没有为 preact 配 JSX，用 JSX 会污染 `tsconfig`。模型侧覆写 `getNodeStyle` / `getTextStyle`，样式取自 `lane.color`。

### 连线（`src/editor/edges/FlowEdge.ts`）

自定义连线 `flow-edge`，按 `kind` 出两种样式：`main` 棕色实线、`exception` 红色虚线，都不画箭头（与参考图一致）。覆写 `updatePoints()` 做「右出左进 + 肘形拐弯」的路由；若 `waypoints` 存在则直接用 `waypoints` 覆盖自动路由。连线文字标签走 `edge.text` 渲染成胶囊样式。

注意沿用现有 `src/flow/MindMapEdge.ts` 已验证过的一条经验：**拖动节点时端点要跟着走，靠的是覆写 `updatePoints()`**，因为 `PolylineEdgeModel.moveStartPoint/moveEndPoint` 会调用它。

### 背景（泳道表头 / 斑马行带 / 步骤号列）

两条硬要求：**必须随画布缩放平移同步**，且**绝不能出现在导出的 JSON 里**。

已核实：`BackgroundOverlay` 只是 CSS `background-image`（不同步画布变换，做不了对齐坐标的列），`Grid` overlay 只支持等距网格（表达不了泳道列宽不等）。所以没有现成 API 能用。

**首选方案**：把表头与行带做成不可交互的 LogicFlow 节点（`isSelectable: false`、`isDraggable: false`、低 `zIndex`），它们天然随画布变换同步。导出安全由**结构**保证而不是靠小心：序列化统一走 `toDoc()`，它**按 type 白名单**只读取用户节点与连线，背景类型在代码层面就不可能进入文档。

**定案规则（P1 实测决定）**：若实测发现背景节点会污染撤销栈（例如撤销一次就退回「无背景」状态），则退到备选方案——用一个随 `getTransform` HOC 同步的独立 SVG 图层绘制背景。判断标准只有这一条，在 P1 结束时给出结论。

## 7. 编辑器 UI 与交互

### 外壳

`App.vue` 变成外壳，顶部模式切换：**思维导图 / 流程图**。`WmsStructure.vue` 原样保留。用 `v-if` 切换而非 `v-show`：LogicFlow 的 `frameGraph()` 依赖容器的 `clientWidth/Height`，隐藏状态下容器尺寸为 0 会把图缩到看不见；`v-if` 让每个模式激活时重新挂载并重新取景。

### 界面：只有画布 + 左栏素材 + 一条顶栏

- **顶栏**（直接写在 `FlowEditor.vue` 模板里，不单独开组件）：添加泳道、删除泳道、步骤 +/−、导出 JSON、导入 JSON、导出 PNG、重置为示例。
- **左栏素材**：一个可拖拽的节点项，拖到画布即在格子处创建下一个可用编号（A02、A03…）的节点。
- **中央** LogicFlow 画布。

**不做**右栏属性面板、不做文档管理、不做复制粘贴、不做连线手动调走线。

### 交互清单

| 操作 | 实现要点 |
|---|---|
| 建节点 | 左栏拖到画布 → `pointToCell()` 换算成格子；格子被占则**向下**找同列空格子，下到头再向上找 |
| 移动 / 跨泳道 | 拖动结束把像素位置吸附回格子，写回 `laneId` / `step`；配色随泳道变 |
| 改节点文字 | 双击节点，弹一个定位到该节点矩形上的 `<textarea>` 覆盖层，提交后重算高度并重新吸附 |
| 改连线标签 | 双击连线，复用同一个覆盖层 |
| 建连线 | 从节点锚点拖到目标节点（核心自带），默认 `main` |
| 删除 | 删节点时连带删挂在它上面的连线。`Backspace` 是核心自带，**`Delete` 由我们在 `onKeydown` 里补**（已核实核心只绑了 `backspace`，没有 `del`） |
| 撤销 / 重做 | **文档级撤销栈**（约 25 行，写在 `FlowEditor.vue`）。`history` 必须**显式设 `false`** —— 它默认是开启的，内置撤销作用于画布模型，会与文档脱节 |
| 多选 / 对齐吸附 | 纯配置：`multipleSelectKey: 'shift'`、`snapline: true`。不写 UI |
| 增删泳道 | 顶栏按钮；泳道内还有节点时拒绝删除并提示（见 5.1） |
| 步骤 +/− | 减少步骤时越界节点自动上移（见 5.1），**绝不静默删除节点** |
| 泳道改名 | 双击泳道表头，复用同一个覆盖层 |
| 节点编号 | `idGenerator` 生成 A 开头的下一个可用编号 |

### 三个刻意保留的技术取舍

- **不用 `DndPanel` 插件，自建素材面板**。它的落点是像素坐标，我们反正要再吸附一次；它还会带进自己那套 CSS，与参考图观感冲突。自建约 30 行，完全可控。
- **不依赖核心的 `snapGrid`**。它是**等距**网格，表达不了「泳道列宽不等」；格子吸附由 `geometry.ts` 自己算。
- **双击编辑不用 LogicFlow 内置的 `editText`**。自定义节点自己画多行正文（`getText()` 返回 null），而内置编辑依赖它自己的 `BaseText` 组件，两者不能共存。改用覆盖层后 `wrapText` 保持「算高度」与「画几行」的单一事实源——否则就是让两套度量去赌一致，那是长期的错位来源。代价是约 40 行覆盖层 + 一次坐标换算。

## 8. 存储与导入导出

`src/editor/storage.ts`，**一个** localStorage key：`wms-flow:doc`（单份文档）。

编辑时防抖自动保存。加载时过 `validateDoc()`：校验 `schemaVersion`、结构完整性（连线两端节点存在、节点 `laneId` 存在、`step` 在 1..stepCount 内、无两个节点落在同一格）。**校验失败给一条可读错误并保留原数据**，不要白屏、不要静默清空。导入/导出就是一份 `FlowDoc` 的下载/上传。「重置为示例」清掉本地存储回到 `harvestInboundDoc`。

转录是人工的，**P1 交付时请对着原图核一遍**——这是整件事的验收基线，错了会一路埋进编辑器。

## 10. 验证方式

新增 **Vitest**（devDependency，仅测试用），`pnpm test` 运行。仓库原本 `pnpm build` 是唯一验证手段，此后 CLAUDE.md 需同步更新。

单测覆盖（都是纯函数，不依赖画布）：

1. **几何推导**：给定 lanes/stepCount，验证 `laneLeft` 累进、节点宽 = 列宽 − 2×内边距、`x` 落在列中心、`y` 落在行带中线；增删泳道后已有节点的新坐标符合预期（这是「自动重排」的机器化验收）。
2. **文本换行**：CJK/Latin 混排的换行与高度估算，含超长单词、空文本、单字边界。
3. **文档校验**：`validateDoc` 对各类坏数据（连线指向不存在节点、节点落在重复格、`step` 越界、`schemaVersion` 不匹配）给出预期错误；导出→导入往返后文档深度相等。
4. **守恒规则**（第 5.1 节）：把 `stepCount` 调小后越界节点被上移且**总数不变**（不丢节点）；删除仍有节点的泳道被拒绝、文档不变。
5. **示例图完整性**：21 个节点无重复格、所有连线两端都存在、所有 `laneId` 有效。

手工验收清单（写进使用说明）：沿第 1 节验收标准逐条对图核对。

## 12. 风险与已知不确定项

1. **示例图转录准确性**（最大风险）。人工逐条转录 21 节点 + 全部连线，靠 P1 时用户对图核对兜底。
2. **背景节点是否污染撤销栈**。已定案规则见第 6 节：P1 实测，若污染则退到独立 SVG 图层。
3. **自定义节点视图要用 preact 的 `h()`**，项目没有 preact JSX 配置。已用显式 `h()` 调用规避；P1 会验证多行文本与徽章的排版效果。
4. **仓库不是 git 仓库**，没有版本控制兜底，所有改动不可 diff 回滚。改动前建议用户自行备份 `src/`。
