# RK-001「大改小」改「改刀料」并直入半成品立库 设计

- 日期：2026-11-10
- 状态：待实施
- 影响：软件蓝图 V2.5 → V2.6（RK-001 重写），`jeecg-boot-module-wms` 原材料到货链路 + 前端到货登记页，改制单模块退役
- 结论先行：**改刀料不再是一道加工工序，而是与段差棒同口径的直入物料**——到货登记 → 分配立库货位 → 堆垛机入库 → 库存入账 → 回写采购收料单；流程里去掉「大改小加工」「生成改制单」两个步骤。

## 1. 需求（用户口径）

1. 蓝图里「大改小」全部改为「改刀料」。
2. 改刀料的处理方式改为**与段差棒一样，直接入半成品立库**。
3. 去掉「大改小」和「生成改制单」的步骤。
4. 据此生成新蓝图与项目代码。

**页码核对**：V2.5 docx 中 RK-001 实际在第 **8** 页（第 10 页是 RK-005）。流程名唯一，改动对象确认无误；新版本会因 RK-001 少两行而重排，页序以新 docx 为准。

## 2. 现状（代码事实）

`WmsRawInboundServiceImpl.receive()` 按 `handlingType` 分两条完全不同的路：
- `DIRECT`（段差棒直入）：单据「待分配」→ `putawayRaw` 选库位 → 「已审核」→ 库存入账 → 回写**采购收料单**。
- `CONVERT`（大改小）：单据登记即「已审核」、`sync_status=无需同步`、**原材料不入 WMS 库存**、直送车间；产出走**改制单**模块（`WmsConversionServiceImpl` 完成时生成生产入库单）。

证据：`WmsRawInboundServiceImpl.java:145-148, 208-217, 337, 422-424`；`WmsConstants.java:1005-1034`；前端 `raw/raw.data.ts:13-14, 66-74`、`raw/index.vue:8-15, 70, 88-112`、`RawReceiveModal.vue:63-67, 331-333`。

改制单菜单：`sys_permission` id `1910000000000000973`（入库管理 → 改制单）+ 4 个按钮点（`wms:conversion:*`）。

## 4. 不改的部分（明确划界）

- 历史数据：`wms_inbound_order` 里既有的 CONVERT 单据仍保持「已审核/无需同步」状态，**不做数据迁移**（其原材料确实直送车间且已入 ERP 账，改动会凭空造库存）。新规则只影响此后的登记。
- 改制单表与代码：保留（可回滚）。
- 其余 16 条流程：一字不动。
