# 技术债清理 Implementation Plan（2026-11-10）

**目标**：清掉 `plans/2026-10-29-yx-wms-待办清单.md` §5 中仍标记「未修」的 7 项代码级技术债。

**范围外**（不是代码能修的，单独说明，不动代码）：

- §5-25 多实例部署：涉及共享存储与分布式锁，属部署期改造。

**基线**：模块单测 1576 全绿（2026-11-10 实跑）。每项完成后必须保持全绿。

## 逐项做法

| # | 技术债 | 做法 | 验收断言 |
| --- | --- | --- | --- |
| 1 | §5-15b 盘盈亏回写缺金蝶库存前置校验 | `WmsStocktakeErpWriterImpl` 注入 `IWmsKingdeeInventoryReader`；盘亏分录提交前按「仓库\|物料\|批号」查 STK_Inventory 的 `FBaseQty`，不足即 `fail`（不回写）；查询自身失败只 warn 放行（基础设施故障不阻断业务） | 库存不足返回失败文案且不调用 save；库存充足正常保存；查询异常仍继续 |
| 2 | §5-16 审计 `bizNo` 对改制单/不良记录仍是雪花 id | `WmsAuditAspect.resolveBusinessNo` 增两条回查：改制单 → `conversionNo`（bizRef=生产订单号）、不良记录 → `sourceBillNo`（bizRef=物料编码） | 传 19 位 id 时 bizNo 变成业务单号；查不到保留原 id |
| 3 | §5-18 权限守卫单测是手工清单 | `WmsControllerPermissionsTest` 改为按包扫描 `@RestController` 自动发现，手工清单只作「扫描必须命中」的兜底断言 | 新增控制器漏标 `@RequiresPermissions` 时测试自动失败 |
| 4 | §5-19 `cancelPick` 先撤物理任务后改单据状态 | 顺序改为：条件更新状态（失败即抛）→ 释放分配 → 撤销设备任务（失败只 warn） | 状态已被并发改走时不调用任务撤销；正常情况下三件事都发生 |
| 5 | §5-20 同步成功后 `last_sync_error` 不清空 | 出库 `patchOrderStatus`/`patchOrderStatusFrom`/`updateStatus`、`WmsOutboundTaskServiceImpl` 同款、调拨下发成功路径，改为 `UpdateWrapper.set("last_sync_error", null)` 显式清空 | 成功后列表失败原因列为空 |
| 6 | §5-21 受托不良扣减候选池未排除废品仓 | `deductConsignedInventory` 候选行按库位过滤掉废品仓（`warehouse_type=SCRAP` 下所有库位） | 废品仓库存不参与扣减；废品仓独占时按「可用不足」拒绝 |
| 7 | §5-23 改制单与产出入库单只有 remark 字符串关联 | 新增 Flyway `V3.9.5_59`：给 `wms_production_inbound` 加 `conversion_order_id`、`source_material_code`；`WmsProductionSubmitDTO` 透传，`submit()` 落库；改制完成时写入 | 完成改制后入库单两列非空，可按改制单 id 反查 |

## 风险与回滚

- 前三项只改逻辑，无 schema 变更；#7 是加列（`IF NOT EXISTS` 幂等），可回滚为不读该列。
- #1 只影响回写判定，不影响 WMS 本地盘点与库存调整；金蝶未配置时行为不变（配置缺失仍走原 NOT_CONFIGURED 分支）。
- 每项独立提交，便于单项回退。
