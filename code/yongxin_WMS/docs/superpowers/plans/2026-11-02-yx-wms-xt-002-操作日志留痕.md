# XT-002 操作日志留痕 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让每一次 ERP↔WMS 的数据流动和 WMS 内部关键操作都留下带**变更前后值**的不可篡改记录，并能凭一张错单号查出它在 WMS 影响了哪些单据与库存。

**Architecture:** 新增 `wms_audit_log` 单表（只增不改），写入口统一为 `IWmsAuditLogService.record(AuditEvent)`；HTTP 通道由 `@WmsAudit` 切面采集，定时任务/回写/设备回调在 service 内显式调用；影响面由实时 join 当前库的只读服务提供；导出复用 KC-004 的异步任务表但需先加 `taskType` 分发。附带修复 ERP 作废工单进不了 WMS 的四处断点（方案 B：新增终态「已作废」）。

**Tech Stack:** Spring Boot 4.1 / Java 17 / MyBatis-Plus / Flyway / AOP / Vue3 + ant-design-vue / AutoPoi（**不引 EasyExcel**）

**Spec:** `docs/superpowers/specs/2026-11-02-yx-wms-xt-002-操作日志留痕-design.md`

## Global Constraints

- **审计写失败不阻断业务**（fail-open）：`record()` 内部 `try/catch`，只 `log.error` + 告警，绝不向外抛异常。回写场景尤其重要——金蝶已落单，WMS 回滚只会两边不一致。
- **审计记录不可变**：实体无 `update_time`/`deleted_at`；不提供 update/delete 接口；DB 加 `BEFORE UPDATE` 触发器（**不挡 DELETE**，保留期清理要用）。
- **`biz_no` 必须始终有值**：按行同步的场景用「单号#序列#工序号」保证唯一，禁止写 null（这是 `wms_sync_log` 今天的毛病）。
- 前后值只存**关键字段 diff**（JSON），不存整行、不重复存 ERP 大报文（报文仍由 `wms_sync_log.request_payload` 承载）。
- 保留期配置项 `audit.retention.days`，默认 `365`，**前端系统配置页可按天调整**。
- 权限码 `wms:audit:list` / `wms:audit:export`，只授审计员 + 管理员。
- 构建/测试一律 `bash /d/tools/m.sh -P dev …`；改完 wms 模块必须 `install` + **重启后端**。
- 单测命令带 `-Dsurefire.failIfNoSpecifiedTests=false`。
- 前端 `vue-tsc` 1.8 与 TS 5.9 不兼容，用 `npx vite build` 验证语法。

## Review Focus

1. **审计库不可用/表不存在时业务照常** —— 对账、回写、设备回调都不能因为审计失败而中断。→ Task 2 `record_swallowsException_neverThrows`
2. **影响面查不到已删除单据** —— 用户要的是"这张单干了什么"，若单据已被删，页面必须明确说"已删除，仅日志可见"，不能静默空白。→ Task 5 `analyze_whenDocumentsDeleted_reportsGap`
3. **作废工单被 WMS 继续执行** —— 已作废的工单不能再提交入库/领料，否则纠正完又产生新错误。→ Task 9 `cancelledOrder_blocksSubmitAndPick`
4. **保留期配成 0 或负数** —— 不能把全部日志瞬间删光。→ Task 8 `clean_invalidRetention_skipsInsteadOfWiping`
5. **导出无数据** —— 不能生成一个只有表头的空文件，页面要直接提示。→ Task 7 `export_emptyResult_doesNotCreateFile`
