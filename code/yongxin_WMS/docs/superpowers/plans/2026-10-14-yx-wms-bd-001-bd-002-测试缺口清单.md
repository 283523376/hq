## 一、缺陷级（当前行为会直接产出错误数据或误导用户）

### G-TRIM（严重）：物料/分类编码既不 trim 也不判空

- **当前行为**：`WmsMaterialServiceImpl.addMaterial` 与 `WmsMaterialCategoryServiceImpl.addCategory` 既不 trim 编码，也不做空值校验（`oConvertUtils.isEmpty` **不做 trim**，`"   "` 不算空）。纯空白编码可入库。
- **对比**：`WmsSupplierServiceImpl`（`trimFields` + 判空）与 `WmsOrderServiceImpl.addOrder`（trim + 判空）都已正确处理。BD-002 的 Review Focus #2 正是为修这类缺陷而设。
- **影响**：`"   "` 与 `""` 在唯一索引 `uk_wms_material_code` / `uk_wms_mat_cat_code` 下是**两个不同的值**，与「编码唯一」的业务语义不一致；可能出现多个「看起来一样」的编码。导出到 Excel 后用户无法分辨。
- **证据**：`WmsMaterialServiceImplTest.addMaterial_currentlyAcceptsBlankCode`、`WmsMaterialCategoryServiceImplTest.checkCodeExists_shouldShortCircuitOnBlankCode`。
- **建议**：为 `addMaterial` / `editMaterial` / `addCategory` / `editCategory` 补 `trim` + 空值校验，并在 `checkCodeExists` 中按 trim 后比对（照抄 `WmsSupplierServiceImpl.checkCodeExists`）。同时补导入路径 `saveImportedRow` 的 trim。

### G-17（中）：空 Excel 不报「文件内容为空」

- **当前行为**：仅表头的 xlsx 解析出 0 行，走 `imporReturnRes(0,0,[])` 的「无错误」分支，返回 `code=200`、`共0行数据全部导入成功！`。
- **期望行为**（用例清单 BD001-T17）：提示「文件内容为空」。
- **影响**：用户下错模板（表头对不上 → 解析出 0 行）时会看到「全部导入成功」，误以为数据已入库。
- **证据**：`WmsMaterialControllerTest.importExcel_emptyFile_shouldReturnZeroRowsMessage`。
- **建议**：在控制器 `importExcel` 中，当解析结果为 0 行时返回 `Result.error("文件内容为空")`。

## 五、测试基础设施层面的两个坑（供后续维护者参考）

这两条不是产品缺陷，但会让后续写的测试**静默失效**，已在计划文档的 Global Constraints 中固化：

1. **`QueryWrapper` 的条件参数是惰性填充的**。不调 `getSqlSegment()` 时 `getParamNameValuePairs()` 恒为空 `{}`——「必须不包含」的断言会退化成**永真断言**（实际什么都没验证），「必须包含」的断言会误报失败。断言写法：先 `String sqlSegment = wrapper.getSqlSegment();` 再断言列名。
2. **`QueryGenerator` 只从实体字段值构造条件**，`request.getParameterMap()` **仅**用于 `_begin`/`_end` 区间与排序。测试里把筛选值只塞进 request 参数会构造出**零条件**；必须设在实体入参上（与「前端查询参数 → Spring 绑定进实体」的真实链路一致）。
