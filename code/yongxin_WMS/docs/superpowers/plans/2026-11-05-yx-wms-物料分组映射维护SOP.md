# 物料分组映射维护 SOP

- 日期：2026-11-05
- 适用：金蝶物料分组 → WMS 分类类型（原材料/半成品/成品/辅料）的日常维护
- 背景：`category_type` 是 RK-001 外购/受托原材料入库的**前置条件**——物料没有分类类型就过不了入库校验。
  金蝶的物料分组（材质+工艺语义，2039 个）与 WMS 的仓储分类不对应，靠本映射表翻译。
- 关联：
  - 表 `wms_material_group_map`（Flyway `V3.9.5_51`）
  - 端点 `/wms/materialGroupMap/*`（权限 `wms:materialGroupMap:*`）
  - 分类同步 `POST /wms/materialCategory/sync-from-kingdee`
  - 物料同步 `POST /wms/material/sync-from-kingdee`

---

## 1. 什么时候要做

| 触发 | 动作 |
| --- | --- |
| 金蝶新增了物料分组 | 认领新分组 → 映射 → 双同步 |
| 业务上发现某类物料入库被拒「不是原材料」 | 查该物料分组的映射是否缺失/错误 |
| 映射标错需要改 | 更新映射行 → 双同步 |
| 某分组不再需要 | 删除映射行（注意 §5 第 3 条） |

**不需要做**的时机：物料增减、物料改名——这些走物料同步自动更新，与映射无关。

## 2. 日常维护流程（五步）

```
① 看缺口 → ② 定类型 → ③ 录映射 → ④ 分类同步 → ⑤ 物料同步
```

### ① 看缺口：哪些分组还没映射

```
GET /wms/materialGroupMap/unmappedGroups
```

返回**已同步但未映射**的分组，按物料数降序。优先处理物料数多的——
**标完前 631 个分组即可覆盖 80% 物料**，不必求全。

### ② 定类型：业务判断该分组属于哪类

四选一（只能这四个值，其他一律被拒绝）：

| 分类类型 | 判断标准（供参考） |
| --- | --- |
| 原材料 | 未加工的棒料、整支料、外购原料（如 `F.Y.002 整支料`） |
| 半成品 | 处于工序中间态：焊接钻针、段差精磨、一焊/二焊、大改小 |
| 成品 | 完工形态的刀具/成品件 |
| 辅料 | 低值易耗品、五金部件、包装、工具（如 `75 低值易耗品`、`PJ.1301.0202.C 五金部件`） |

> 参考数据：金蝶侧历史映射表（`docs/superpowers/plans/2026-11-05-yx-wms-物料分组映射表.csv`）里有 40% 物料的自动标注建议可对照。

### ③ 录映射：批量 upsert

```
POST /wms/materialGroupMap/saveBatch
Content-Type: application/json; charset=utf-8

[{"groupNumber":"Y.P.019","categoryType":"辅料","remark":"机器配件(国产)"},
 {"groupNumber":"Y.X.003","categoryType":"半成品"}]
```

- 按 `groupNumber` 幂等：重复提交是「无变化」，不会产生重复行
- 同批内**任何一行**分类类型非法 → **整批拒绝**（文案会指出第几行）
- 允许的 `categoryType`：`原材料` / `半成品` / `成品` / `辅料`

### ④ 分类同步：把类型刷到分类行

```
POST /wms/materialCategory/sync-from-kingdee
```

这一步把映射表里的 `category_type` 写进 `wms_material_category.category_type`。
**只录映射不跑这步，分类行不会变。**

### ⑤ 物料同步：把分类挂到物料

```
POST /wms/material/sync-from-kingdee
```

按分组编码自动更新 `wms_material.category_id`。跑完后验证：

```sql
SELECT COALESCE(c.category_type,'<未映射>') 分类类型, COUNT(*) 物料数
FROM wms_material m JOIN wms_material_category c ON c.id=m.category_id
WHERE m.deleted_at=0 GROUP BY c.category_type ORDER BY 物料数 DESC;
```

## 3. 修改/删除映射

- **改类型**：重新 `saveBatch` 同一 `groupNumber` 新类型 → 重跑 ④⑤
- **删映射**：`DELETE /wms/materialGroupMap/{id}`
  ⚠️ **删除不会回滚**已同步到分类行的 `category_type`（有意设计，防止误删导致大批物料掉分类）。
  如果确实要清掉某分组的类型：删映射后，手工把 `wms_material_category.category_type` 置 NULL，
  再重跑 ⑤。

## 4. 验证与排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 物料入库报「不是原材料」 | 该物料分组的映射缺失或映射成了别的类型 | ①③④⑤ 走一遍 |
| 映射保存报「分类类型非法」 | 类型不在四值之内 | 核对取值 |
| `unmappedGroups` 里仍有刚映射的分组 | 正常——列表只看分类行类型，重跑 ④ 后消失 | 无需处理 |
| 分类同步报金蝶错误 | 同步开关关闭 / 凭据缺失 | 检查 `KINGDEE_ERP_ENABLED` 与 5 项凭据 |
| 同步完成后物料数不变 | 分组下没有物料，或物料已是该分类 | 正常 |

## 5. 注意事项（踩过的坑）

1. **顺序不能反**：③→④→⑤。只跑 ⑤ 不跑 ④，物料挂了分类但分类没有类型，入库照样被拒。
2. **旧配置项 `kingdee.material-group-map` 已废弃**：在系统配置页改它**没有任何效果**（生产代码不再读取）。
   映射的唯一生效入口是本 SOP 的映射表。
3. **删除映射不回滚分类类型**（见 §3）。
4. **费用类供应商不能用于收料通知单**——与本 SOP 无直接关系，但同为「金蝶主数据分组语义」陷阱，
   排查入库问题时一并检查。
5. 映射是**精确分组编码**匹配，不支持前缀/通配。金蝶新增分组不会自动继承同类映射，必须显式登记。

## 6. 权限

| 动作 | 权限码 |
| --- | --- |
| 查看（list/listAll/unmappedGroups） | `wms:materialGroupMap:list` |
| 批量保存（upsert） | `wms:materialGroupMap:create` 或 `edit` |
| 删除 | `wms:materialGroupMap:delete` |
