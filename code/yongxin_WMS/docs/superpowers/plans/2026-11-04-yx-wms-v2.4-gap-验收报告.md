## 7. 未验证项（必须如实说明）

### 7.1 真账套端到端：**阻塞，未做**

阻塞原因：5 个新单据的 formId 全部未配置，`WmsConfigKey` 默认空串，
Reader/Writer 按设计显式抛错。需要先在金蝶 BOS 在线控制台确认并填写：

| 配置键 | 用途 |
| --- | --- |
| `kingdee.form.purchase-order` | 外购订单读取（到货登记校验） |
| `kingdee.form.consigned-order` | 受托订单读取 |
| `kingdee.form.purchase-inbound` | 段差棒直入回写采购入库单 |
| `kingdee.form.consigned-inbound` | 受托加工材料入库单 |
| `kingdee.form.purchase-return` | 受托不良退货（采购退货单） |

**这不是代码缺陷，是外部依赖**：formId 需在金蝶侧确认，配置前原材料入库链路一律在第一步失败。
因此以下 4 条端到端链路**没有跑过**：

1. 段差棒采购入库：到货 → 上架 → 库存入账 → 金蝶采购入库单
2. 受托到货：到货 → 上架 → **受托库存行（`ownership_type=CONSIGNED`）** → 受托加工材料入库单
3. 大改小：生产订单 → 改制单 → 生产入库 → PRD_INSTOCK 回写
4. 受托不良退货：登记 → 退货 → 采购退货单

### 7.2 其他未覆盖

- **受托库存与自有库存隔离**只做了单测断言；本机 `wms_inventory` 只有 2 行自有且数量为 0，
  没有受托行，页面上无法用真实数据区分「默认不显示受托」的效果。
- `pnpm build` 脚本是纯 `vite build`，**不含 `vue-tsc`**；新增的 9 个 `.vue/.ts` 只过了 eslint 与打包，
  没做类型检查（全仓历史类型问题过多，全量 tsc 不可行）。
- `GET /wms/defect/records` 直接绑定实体，实体时间字段无 `@DateTimeFormat`：实测传
  `createTime=2026-11-04` 会 500（`Failed to convert ... to java.util.Date`）。前端已不发时间参数，
  但这是接口契约的已知粗糙点，后续要加日期区间筛选必须先改 DTO。
- WCS/RMS 设备物理搬运未接真机，领料设备的写入只是数据记录。
