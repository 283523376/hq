# XT-001 不良品处理出口 设计方案

- 日期：2026-11-02
- 状态：待确认
- 需求来源：蓝图 `YX-WMS-XT-001 不良品处理流程`

---

## 1. 需求与现状

### 1.1 蓝图原文

> 贯穿入库和出库环节。检验不合格或生产不良品，需在系统中记录并转入废品仓，**支持后续报废出库或退货**。

流程 6 步：扫码 → 录数量原因 → 分配废品仓库位 → 上架更新库存 → 记录台账 → 同步 ERP/MES。

### 1.2 现状盘点（2026-11-02 实测）

| 环节 | 现状 | 缺口 |
| --- | --- | --- |
| 不良品入库（1-4 步） | ✅ RK-005 已实现：生产入库按 `goodQty/badQty` 拆分，不良品进废品仓默认位 `FPC-DEFAULT` | — |
| 记录台账（5 步） | ⚠️ 数据在库里，但**没有专门视图**，只能去库存台账按仓库筛 | **缺独立台账页** |
| 同步 ERP（6 步） | ✅ 纯不良品回写金蝶其他入库单 `STK_Miscellaneous` | — |
| **处置出口** | ❌ **没有**：出库类型只有「生产领料/销售/外协/样品」 | **本期主体** |

### 1.3 本期范围（用户 2026-11-02 拍板）

- ✅ **只做报废出库**
- ❌ 不做退货（采购入库 2026-10-19 已停用，供应商退货无上游入口；客户退货属销售域，需求未定，另立项）
- ✅ **独立「不良品台账」页面**

## 2. 方案

### 2.1 数据模型：不新建表

报废出库复用现有 `wms_outbound_order`，新增一种类型：

```
outboundType = "报废出库"     // WmsConstants.OUTBOUND_TYPE_SCRAP
```

**为什么不新建表**：报废出库在单据语义上与领料/销售出库同类（都是「货从库存出去」），
复用能直接获得：单号生成、状态机、审计打点、库存扣减、金蝶回写框架。
新建表会让这些能力各写一遍。

**新增字段：无**。报废出库需要的「报废原因」复用 `remark`，审批信息走现有状态字段。

### 2.2 报废出库的状态流转：一步到位

```
草稿 → (提交) → 已完成
```

**不走** 分配 → 下发 → 复核 → 确认 这套流程，原因：

- 废品仓是**固定库位**（`FPC-DEFAULT` 或配置的废品仓默认位），没有「分配库位」的概念
- 没有设备搬运（废品不需要堆垛机/RMS 调度）
- 多一道确认只是让操作员多点两次

**但要留审计**：报废是**减库存**的不可逆动作，必须记录谁在什么时候报废了什么（走 XT-002 的 `@WmsAudit`）。

### 2.3 不良品台账

**数据来源**（全部实时查询，不建快照）：

| 分组 | 来源 |
| --- | --- |
| 当前不良品库存 | `wms_inventory` 关联 `wms_warehouse.warehouse_type = '废品仓'` |
| 来源追溯 | 按 物料+批次 反查 `wms_production_inbound` 的 `badQty > 0` 记录（谁生产的、哪张工单） |
| 处置历史 | `wms_outbound_order` 中 `outbound_type = '报废出库'` 且明细含该物料的记录 |

**页面能力**：

- 按 物料编码/名称、批次、库位、时间区间 过滤（沿用刚上线的模糊匹配）
- 每行显示：物料、批次、当前数量、所在库位、来源工单、最近一次报废时间
- 行操作「报废出库」→ 弹窗填数量 + 原因 → 提交
- 顶部「批量报废」：勾选多行一次提交

### 2.4 报废出库的执行

```
用户填数量+原因
  → 校验（数量 > 0 且 ≤ 可用量；废品仓库存必须存在）
  → 建 wms_outbound_order（type=报废出库，status=草稿）
  → 扣减库存（wms_inventory，锁定行）
  → 状态置「已完成」
  → 回写金蝶其他出库单 STK_MisDelivery
  → 审计留痕（action=作废/报废，channel=界面操作）
```

**失败策略**：库存扣减与建单在**同一事务**内；金蝶回写**在事务外**，失败只标记
`sync_status=同步失败` 并允许重试——金蝶不可用不能阻断仓库作业（沿用现有出库的做法）。

### 2.5 金蝶回写：其他出库单

单据类型：`STK_MisDelivery`（其他出库单）。

必需字段（**需真账套实测确认**）：
- `FStockOrgId`（库存组织，101）
- `FStockId`（仓库，废品仓对应的金蝶仓）
- `FMaterialId`、`FQty`、批号（如启用）
- `FStockLocId`：**101 组织仓库未启用仓位管理，不带**（2026-10-28 已证实）

> 金蝶「其他出库单」可能有审批流（与「其他入库单」一致），Save+Submit 后状态可能停在
> 「已提交」而非「已审核」。按自动化优先原则先做到 Submit，审核交给金蝶工作流。

## 3. 权限

| 权限码 | 授予 |
| --- | --- |
| `wms:defect:list` | 不良品台账查询 |
| `wms:defect:scrap` | 执行报废出库 |

按现有惯例，默认只授管理员 + 仓管；审计员可查不可报废。

## 4. 验收标准

1. **台账可见**：废品仓有库存时，台账页按物料/批次能查到，并显示来源工单
2. **报废成功**：选中一行报废 1 件 → 废品仓库存 -1、生成报废出库单、状态已完成
3. **防超报**：数量超过可用量 → 明确拒绝，库存不变
4. **金蝶回写**：真账套开出 `STK_MisDelivery`，单号回存；失败时不阻断，标记可重试
5. **审计留痕**：审计日志能查到「谁在何时报废了什么、多少、什么原因」
6. **不误伤**：常规库存（非废品仓）不受影响

## 5. 风险

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| **金蝶单据不确定** | `STK_MisDelivery` 的必填字段与审批流未实测 | 先写回写器 + 单测，真账套跑一次再定稿 |
| **废品仓可能没配** | `defect.warehouse.code` 为空时回退到 `WAREHOUSE_TYPE_SCRAP` | 沿用现有 `resolveScrapLocationId` 逻辑 |
| **报废不可逆** | 扣了就回不去 | 走审计 + 二次确认弹窗 |
| **与盘点/调拨的冲突** | 报废时该库位可能正被盘点冻结 | 复用现有冻结校验 |
